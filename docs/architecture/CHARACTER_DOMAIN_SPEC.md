Core 수치·정책 event-affect-v3-dev1은 유지하고 해석 지침은 event-interpretation-v3-dev2로 변경했다.

읽은 모든 source/state 참조는 여전히 기록 전체의 의존성으로 유지한다. 모델용 후보를 제외해도 이 삭제 경계를 줄이지 않으므로 연결된 episode 삭제가 같은 기록의 입력 감정도 함께 무효화할 수 있다. 범위별 독립 삭제나 DB 저장을 구현했다고 보지 않는다. 자세한 소유권은 계획 §4와 결과를 따른다.

## 1. 책임과 규칙의 우선순위

Core는 확정된 사건과 현재 상태를 받아 **다음 상태, 근거, 행동 계획**을 반환한다. DB·Ollama·TTS·아바타를 직접 호출하지 않는다.

우선순위는 다음과 같다.

1. 입력·출처·중복·취소·세션 유효성.
2. 코드로 확인한 활동 결과와 실제 출력 결과.
3. 현재 상대·목표·대화 차례.
4. 감정·기분·관계·반복 경험.
5. 말투와 표현.

감정이나 LLM의 해석이 앞 단계의 사실과 권한을 덮어쓰지 못한다. 상태 갱신은 결정적이며 MVP에서는 확률적 행동 선택을 사용하지 않는다. 같은 상태·사건·시각·설정 버전이면 같은 결과를 만든다.

이 문서는 도메인 의미와 초기 수치의 원본이다. DB 컬럼·중복 키·재집계는 [DB 설계 명세](./DATABASE_SPEC.md), 전송 메시지 이름은 [런타임 통신 명세](./RUNTIME_PROTOCOL.md)에서 정하고, 초기 기술 설계의 예시 JSON과 다른 부분은 구현 시 이 규칙에 맞춘다.

## 3. 사건 수용과 상태 전이 순서

### 3.1 사건의 구분

| 사건 | 감정·관계의 근거가 되는 조건 |
|---|---|
| 채팅·음성 최종 발화 | 주의에서 선택되고 해석이 채택됨 |
| 부분 전사 | 근거가 되지 않음. 자막·듣기 상태에만 사용 |
| 활동 시작·힌트 사용·답 판정 | 등록된 활동 adapter가 실제 결과를 발행 |
| 발화·자막 출력 결과 | 활성 출력 클라이언트가 보고한 전달 범위 |
| 세션 종료 정리 | 기존 근거를 묶을 뿐 같은 감정·관계를 다시 증가시키지 않음 |
| 타이머 | 시간 경과·Agenda 조건 평가. 새로운 칭찬·실패로 취급하지 않음 |
| 기억 정정·삭제 | 관리자 입력. 무효화와 재집계만 수행 |

동일 `source_event_id`의 재처리는 상태 변화를 만들지 않는다. 같은 원문을 새 ID로 다시 보낸 경우에는 별도 사건이며 반복 적응의 대상이다. 작업 재시도와 실제 반복 경험을 구분한다.

### 3.2 적용 순서

```text
중복·출처·세션·입력 revision 확인
→ 적용 시각까지 감정·기분 감쇠
→ 관측 여부와 해석 유효성 확인
→ 반복 수와 당일 근거 상한 계산
→ 사건 자극과 관계 근거 적용
→ 활동 상태·작업 기억·필수 사건 기억 갱신
→ 대화 차례와 목표를 보고 행동 선택
→ 상태·근거·출력 계획을 함께 commit
→ 실제 실행 결과를 후속 사건으로 수신
```

시각은 런타임이 제공한다. 실행 중에는 역행하지 않는 경과 시간을 사용하고 재시작 때는 저장 시각과 UTC 시각 차이를 0 이상으로 보정한다. 미래 날짜·늦게 도착한 과거 사건을 이유로 상태 시간을 뒤로 돌리지 않는다. 원래 사건 시각은 기록용으로 별도 보존한다.

주의 선택 자체는 확정 원문을 작업 기억에 넣을 수 있다. 그 원문의 감정·관계 효과는 채택된 해석으로 한 번만 적용한다. 선택·해석·출력 ACK는 별도 단계 ID를 사용해 하나의 원본이 여러 번 자극을 만들지 않게 한다.

## 4. 주의 선택

모델을 호출하기 전에 메타데이터로 후보를 고른다. 관계 점수로 처음 보는 상대를 영구적으로 밀어내지 않는다.

초기 규칙:

- 확정 입력 후보는 최대 100개, 채팅 유효시간은 수신 후 20초.
- 이미 처리했거나 삭제된 입력, 같은 ID의 재전송은 후보에서 제외.
- 명시적인 응답 연결 또는 캐릭터 언급이 있는 채팅을 일반 채팅보다 우선.
- 활성 마이크의 확정 발화를 채팅보다 우선. 마이크 입력 시작은 즉시 출력 취소 경로로 전달.
- 같은 우선순위에서는 수신 순서. 다른 사람의 유효 후보가 있으면 같은 상대를 세 번 연속 선택하지 않음.
- 선택한 입력은 해석 중 새 일반 채팅 때문에 교체하지 않음. 취소·입력 정정·세션 종료는 예외.
- 실행 슬롯이 비었을 때만 다음 해석 작업을 시작. 오래된 후보를 뒤늦게 모두 읽지 않음.

세션 제어·활동 결과·재생 결과·정정은 주의 경쟁을 거치지 않는다. 입력 과부하 때문에 내부 완료 사건이 누락되어서는 안 된다. 사용자 입력 선택과 시스템 사건 처리는 별도다.

`ignored` 입력의 원문은 운영 로그에서 확인할 수 있으나 캐릭터의 작업 기억·사건 기억·관계 근거로 쓰지 않는다. 이후 사용자가 다시 말하면 새 입력을 선택해 이해할 수 있다.

여기서 `ignored`는 주의 선택에서 읽지 않은 입력의 상태다. §10.1의 관측 후 의도적 침묵과 다르며, 발화하지 않았다는 이유로 유효한 관측 입력을 미관측으로 되돌리지 않는다. 기존 Plan의 `ignore` 행동과도 같은 의미로 취급하지 않는다.

## 5. 해석 계약

| 필드 | 허용 의미 |
|---|---|
| `target` | character / activity / other / quoted / unknown |
| `act` | greeting / question / praise / criticism / teasing / hint / help_offer / decline / other / unknown |
| `strength` | 0 없음, 1 약함, 2 명확함, 3 강함 |
| `hostility` | 0 없음, 1 날카로움, 2 직접 비하, 3 명백한 공격 |
| `goal_relation` | helps / blocks / unrelated / unknown |
| `uncertain` | 근거 부족·다중 해석 여부. 보정된 확률이 아님 |
| `evidence_refs` | 이번 입력과 제공된 맥락의 ID. 임의 ID 금지 |

발화 하나의 주된 행위를 선택한다. 복잡한 혼합 발화는 초기에 `uncertain=true`로 처리할 수 있다. 인용·제삼자 발언을 캐릭터 자신에 대한 공격으로 바로 바꾸지 않는다.

`target=unknown`이면 의미 기반 감정·호감 변화는 0이다. `uncertain=true`도 기본적으로 같은 규칙을 따르며 호감은 항상 0이다. 단, C2-S1B의 검증된 칭찬 근거가 있으면 기쁨에만 제한된 강도를 적용한다. 감정 강도의 확신과 명시적 참여 요청의 확신은 분리한다. §10.1의 검증된 대상·행위 근거가 있는 듣기·재접근은 감정 효과 0을 유지하며 처리할 수 있다. 그 외에는 현재 질문을 처리하려면 짧게 확인하고, 그럴 필요가 없으면 듣거나 넘어간다. 확실하지 않다는 이유로 frustration을 올리지 않는다.

**C2-S1B 예외:** Jev v6의 현재 사건·상대·revision에 결합된 envelope를 어댑터가 재검증한다. target=character, act=praise이고 target/act/goal_relation/hostility의 confidence가 각각 .8 이상이며 유일 최빈값, hostility 최빈값은 0이어야 한다. strict appraisal이 불확실할 때 strength 분포를 정규화한 `P(strength>=k)>=.95`의 가장 큰 k(1–3)를 별도 감정 근거로 전달한다. .95는 보수적 정책값이며 교정된 심리 강도/공급자 confidence라는 뜻이 아니다. 원래 uncertain/strength0/원문은 보존하고 확정 appraisal의 기존 강도는 바꾸지 않는다. 이 근거는 관계 호감·관계 반복 계산에서 제외하고 감정 반복 계산에는 포함한다. 공격·활동 효과로 확대하지 않는다.

**2026-10-15 선택형 OpenAI 정책 v4:** v3의 출처·revision·문맥·usage 검증과 yes≥.95/no≤.05, 강도 하한을 유지한다. 하한 근거가 없더라도 검증된 직접 칭찬 yes와 직접 공격 no가 함께 있으면 `kind=praise, strength=1, basis=confirmed_event_baseline`을 전달한다. 이는 모델 강도의 확신이 아닌 작은 긍정 반응의 제품 정책이다. 첫 자극 상한은 .06이며 기존 반복 소비·감쇠·hold 제한을 적용한다. 원문/uncertain/strength0과 관계 제외를 유지하고 공격·활동으로 확대하지 않는다. 강도 하한이 있으면 기존 근거를 우선한다. v3 근거는 v4로 소급 승격하지 않는다. 내부 기쁨 증가가 즉시 happy 표정이나 발화를 요구하지 않는다. 구현·실제 단일 입력의 범위는 [후속 결과](../results/EMOTION_RUNTIME_RESULT.md#restart-and-praise-v4)를 따른다.

칭찬과 비난 자극은 `target=character`에서만 적용한다. 퍼즐의 난이도에 대한 불만은 상대에 대한 부정 근거로 쓰지 않는다. 정당한 오답 지적은 검증기로 확인하고 활동 결과로 처리한다.

사용자가 “네가 맞혔어”, “내가 전에 도와줬잖아”라고 말한 것만으로 활동 성공이나 과거 도움을 생성하지 않는다.

## 6. 감정의 시간 변화

### 6.1 기본 계수

| 감정 | hold | half-life |
|---|---:|---:|
| joy | 4초 | 45초 |
| frustration | 6초 | 90초 |
| surprise | 1초 | 8초 |
| embarrassment | 3초 | 30초 |

모든 감정의 장기 기본값은 0이다. 기준 시각 `s`, hold 종료 `h`, 현재 시각 `t`에서 다음을 사용한다.

```text
decay_seconds = max(0, t - max(s, h))
decayed = value_at_s × 2 ^ (-decay_seconds / half_life)
next = clamp(decayed + applied_stimulus, 0, 1)
```

계산 후 `as_of=t`로 갱신한다. 읽기용 감쇠 계산만 했다면 저장 상태를 반복해서 누적 변경하지 않는다. timer 빈도·UI 프레임 수·댓글 수가 반감기를 바꾸면 안 된다.

hold는 실제 양의 자극이 있고 기존 hold가 끝난 경우에만 새로 시작한다. 반복 칭찬·비난은 최근 10분의 같은 상대·종류에서 첫 사건일 때만 hold 자격이 있다. hold 도중 새 사건이 와도 종료 시각을 밀지 않는다.

예: joy 0.18이 시각 0초에 발생했다면 4초까지 0.18, 49초에 0.09, 94초에 0.045다. 반대 감정이 생겼다고 joy를 0으로 초기화하지 않는다.

### 6.2 사건 자극

표의 값은 반복·상한 적용 전 기본 자극이다. 명확한 사회적 발언은 `strength / 3`을 곱한다. 코드가 확인한 활동 사건에는 이 배율을 쓰지 않는다.

| 사건 | joy | frustration | surprise | embarrassment |
|---|---:|---:|---:|---:|
| 자신을 향한 명확한 칭찬 | +0.18 | 0 | 0 | 0 |
| 자신을 향한 직접 비하: hostility 2 이상 | 0 | +0.18 | 0 | 0 |
| 일반 인사·질문·가벼운 장난 | 0 | 0 | 0 | 0 |
| 새 퍼즐 시작: 문제별 한 번 | 0 | 0 | +0.12 | 0 |
| 실제 제출한 답의 오답 판정 | 0 | +0.20 | 0 | +0.20 |
| 실제 제출한 답의 정답 판정: 문제별 한 번 | +0.30 | 0 | 0 | 0 |
| 사용한 힌트와 성공 결과의 연결 확인 | +0.12 | 0 | 0 | 0 |

비판은 무조건 비하가 아니다. `criticism`이어도 hostility가 0–1이면 직접 비하 자극을 적용하지 않는다. activity 실패의 감정 대상은 해당 퍼즐이며 대화 상대가 아니다.

한 입력에서 사회적 자극은 하나만 선택한다. 활동 성공과 힌트 사용 확인은 서로 다른 검증 사실이므로 별도 근거가 가능하지만, 동일 source로 재전송된 성공은 추가 기쁨을 만들지 않는다.

## 7. 반복 적응과 기분

### 7.1 반복 적응 — 관계 v1과 감정 v2

키는 `(character_id, identity_id, category)`이며 category는 MVP에서 `praise`와 `direct_insult` 두 가지다. 동의어와 바뀐 문구도 같은 종류로 묶는다. 상대별 이력은 세션을 다시 열어도 초기화하지 않는다.

```text
n = 이번 사건 전 최근 600초 동안 관측·채택한 같은 키의 사건 수
habituation = 1 / (1 + n)
candidate = base_stimulus × (strength / 3) × habituation
applied = min(candidate, 최근 600초 자극 상한의 남은 양)
```

상한은 같은 키의 joy 증가량 합 0.30, frustration 증가량 합 0.24다. 실제 감쇠 전의 적용 자극량을 합산하므로 감정이 줄었다고 새 상한을 얻지 않는다. 경계는 `(t-600초, t]`로 통일한다.

같은 시각·strength 3의 칭찬 네 번은 `0.18 → 0.09 → 0.03 → 0`을 적용한다. 세 번째의 원래 후보는 0.06이지만 상한 때문에 0.03만 반영된다. 감정 수치의 최종 0–1 clamp는 그 뒤 적용한다.

ignored 입력·중복 재전송·불확실한 해석은 이 반복 수에 포함하지 않는다. 반복 여부를 캐릭터가 읽지도 않은 댓글에서 학습하지 않는다.

위 무가중 수식은 기존 관계 v1 재계산과 과거 기록의 규칙이다. C2 변경 후 새 감정 적용은 다음 v2를 사용한다.

~~~text
weight(event,t) = max(0, 1 - (t-event.at)/600000), 미래 사건 제외
repetitions = sum(weight)
habituation = 1/(1+repetitions)
consumed = sum(weight × 당시 실제 감정 적용량)
affect_stimulus = min(0.18 × strength/3 × habituation, max(0, cap-consumed))
~~~

기존600초 범위와 cap(.30/.24)은 유지하되 시간에 따라 소비 압력이 줄어든다. 감정 자체의 decay를 예산 회복으로 쓰지 않는다. 상한에 도달한 직후0은 가능하고 시간이 지나면 점진 회복한다. 타이머가 감정을 올리거나 출력 완료가 회복 사건이 되는 것은 아니다. 동시 입력의 .18/.09/.03/0, 기존 hold 기준, 15초 응답 제한은 유지한다. 새 감정 적용량과 관계 재계산용 값은 저장에서도 분리한다. 구형 근거는 기존 적용량을 사용한다.

운영 v6의 반복 키는 여전히 같은 상대/종류다. 2026-10-13 S2의 성취별 계산·검증 경계는 구현했지만 실제 의미 후보가16/20으로 탈락해 운영에는 미채택했다. **의미 구분 기능은 미완료**이며 후속 후보의 실패도 인계에 보존한다. 같은 날 대화 연결 계획에서 이 정밀 구분을 첫 텍스트 MVP의 선행 조건에서 후속 범위로 옮겼다. 새 사건 ID나 문구 차이만으로 예산을 새로 주지 않는다. 0자극은 응답 차단 조건이 아니며 strength0에서도 발화할 수 있다.

### 7.2 기분

```text
시간 경과:
M = 0.60 + (previous_M - 0.60) × 2 ^ (-elapsed_seconds / 900)

새 사건 반영:
M = clamp(M + 0.10 × (applied_joy - applied_frustration
                     - 0.5 × applied_embarrassment), 0, 1)
```

surprise는 기분에 누적하지 않는다. 이 식의 자극은 0–1 clamp 뒤 감정 차이가 아니라 반복·상한을 통과한 사건 자극이다. timer·회고·기억 검색에서 같은 자극을 다시 더하지 않는다.

기분은 표현과 말수에만 약하게 반영한다. 기분이 낮다고 평범한 발언의 hostility를 올리거나 신뢰 근거를 조작하지 않는다.

## 8. 관계와 신뢰 근거

### 8.1 친숙함

- 해당 상대의 첫 관측 확정 발화가 있는 날짜에 +0.02.
- 검증된 힌트 사용과 성공이 있는 서로 다른 퍼즐마다 +0.01, 하루 최대 두 퍼즐.
- 합계 하루 최대 +0.04, 전체 0–1로 제한.
- 날짜 기준은 `Asia/Seoul`. 세션 재시작으로 일일 한도를 초기화하지 않는다.
- 같은 내용 재전송·자신의 출력·부분 전사는 상호작용 날짜를 늘리지 않는다.

첫 관측 발화가 불확실하더라도 “그 상대가 있었다”는 사실은 친숙함 근거가 될 수 있다. 호감이나 신뢰 증가로 연결하지는 않는다.

### 8.2 호감

| 근거 | 후보 변화 |
|---|---:|
| 자신을 향한 명확한 칭찬 | `+0.005 × strength/3 × habituation` |
| 직접 비하 | `-0.005 × strength/3 × habituation` |
| 검증된 힌트 사용과 성공 | +0.015 |
| 인사·평범한 질문·불확실한 발언·부재 | 0 |

상대별 하루 양의 변화 합과 음의 변화 절댓값 합을 각각 0.03으로 제한한다. 둘을 상쇄해 한도를 다시 얻지 않는다. 반복 칭찬·비난에 배정된 감정 자극 상한이 이미 소진됐다면 해당 종류의 호감 변화도 0이다. 전체 affinity는 0–1로 제한한다.

### 8.3 신뢰

MVP에서는 통합 trust 점수나 `trusted/close` 단계를 만들지 않는다. 저장하고 사용하는 값은 다음뿐이다.

- 유효한 도움 근거의 원본 ID 목록.
- 서로 다른 퍼즐에서 확인한 도움 수.
- 도움을 관측한 날짜 수와 최근 시각.

도움 근거는 **시청자의 힌트가 활동에 사용됐다는 이벤트와 이후 정답 판정**이 연결된 경우다. MVP의 검증 가능한 힌트는 활동 adapter가 제공하는 등록된 힌트로 제한한다. 자유 텍스트 조언은 대화에서 검토할 수 있으나 결과 연결을 확인하지 못하면 신뢰 근거로 확정하지 않는다.

이 근거는 “그 사람은 모든 면에서 믿을 만하다”가 아니라 “이 퍼즐 활동에서 힌트를 사용한 경험이 있다”를 뜻한다. 칭찬, 닉네임, 과거 도움의 자기 주장은 근거가 아니다.

같은 퍼즐·같은 상대의 도움 근거는 한 번만 적용한다. 여러 힌트가 있었다면 각 사용 사실은 보존하되 같은 상대의 관계 증가는 한 번이다. 최초 버전의 힌트 예산은 한 번이므로 정상 흐름에서 여러 힌트가 경쟁하지 않는다.

재전송용 이벤트 ID 외에 업무상 중복 키도 둔다. 첫 관측 날짜 근거는 `(상대 ID, 한국 날짜, first_observed)`, 도움 근거는 `(상대 ID, 문제 ID, verified_hint)`로 구분한다. 같은 문제를 다시 열어 새 활동 실행 ID를 만들더라도 독립된 새 도움으로 신뢰를 쌓지 않는다. 원본 사건은 각각 기록할 수 있다.

## 9. 퍼즐 활동과 목표

활동 상태는 `ready → solving → awaiting_hint → solving → solved/ended`를 사용한다. `solving`에서 바로 `solved`가 될 수도 있다.

`problem_id`는 문제의 고정 ID이고 `activity_run_id`는 한 번의 실행 ID다. 답 제출 중복은 실행 ID와 제출 ID로, 서로 다른 문제의 도움 수는 문제 ID로 계산한다. 재시작은 새 실행을 만드는 동작이 아니다.

규칙:

1. 문제·허용된 답 형식만 풀이 모델에 제공한다. 정답과 아직 공개하지 않은 힌트는 검증기 영역에 둔다.
2. 문제당 목표 힌트 예산은 1이다. 힌트를 요청한 것과 실제 공개·사용한 것을 구분한다.
3. 첫 풀이 시도에서는 스스로 답 후보를 구한다. 유효한 후보가 없거나 오답이면 힌트가 남았을 때 요청한다.
4. `candidate_answer`는 풀이 작업의 데이터다. Core가 현재 활동 ID와 형식을 검사한 뒤 adapter에 제출한다. 자유로운 도구 실행 권한을 모델에 주지 않는다.
5. 답 제출 이후 검증기 결과가 도착해야 성공·실패 감정과 기억을 만든다. 대사에서 먼저 성공을 확정하지 않는다.
6. 동일 답의 자동 재제출은 금지한다. 한 문제에서 자동 답 제출은 최대 3회. 소진 시 `pause`하고 사용자 입력을 기다린다.
7. 사용자 명시적 재시도 요청 한 건은 추가 제출 기회를 한 번 주지만 이미 사용한 힌트와 과거 오답을 지우지 않는다. 동일 답의 자동 재제출 금지는 유지한다.
8. 자동 풀이와 힌트 요청을 무한히 반복하지 않는다. 응답 대기에는 새 LLM 호출을 계속 만들지 않는다.

힌트 요청 대상은 현재 세션에서 관측한 상대 중 선택한다. 해당 활동의 유효 도움 근거가 있는 상대, 가장 최근 상호작용한 상대 순으로 고르고 동률은 ID 순으로 고정한다. 아무도 없으면 특정 이름 없이 요청한다. 과거에 있었다는 이유로 현재 없는 사람에게 말을 걸지 않는다.

이 동작을 `continue_activity`의 하위 의도인 `solve`·`submit_candidate`와 `ask/request_hint`로 표현한다. 새로운 최상위 행동 종류를 늘리지 않는다.

## 10. 행동 선택 우선순위

아래 표는 기존 행동 우선순위다. 같은 평가에서 본격 응답은 최대 하나다. 일반 대화의 발화 여부에는 구현된 §10.1을 적용한다. 운영 중지·필수 구성 오류·진행 작업의 배타성은 유지한다.

| 순위 | 조건 | 행동 |
|---:|---|---|
| 1 | 세션 종료, 출력 수동 중지, 필수 구성 오류 | `pause`, 필요 시 진행 출력 취소 |
| 2 | 사용자가 말하는 중 | `listen`, 진행 음성 취소 |
| 3 | 이전 응답·활동 작업이 아직 유효하게 진행 중 | 새 발화 생성 보류. 기존 작업 유지 |
| 4 | 활동 결과가 도착해 설명할 차례 | `acknowledge`, 결과와 현재 상태 표현 |
| 5 | 유효한 질문·요청, 현재 Agenda의 명확한 수락·거절 | 관련 의도 갱신. 질문·요청은 강한 발화 후보이며 §10.1에서 참여 여부 선택. 발화 시 `answer` 또는 `acknowledge` |
| 6 | 대상·의미가 불확실하고 진행을 위해 확인 필요 | `ask`, 짧은 확인 한 번 |
| 7 | 선택된 인사·칭찬·명확한 비난 | `acknowledge`, 반복이면 짧게 또는 `ignore` |
| 8 | 진행 중 퍼즐에 다음 단계가 있고 상대 응답을 기다리지 않음 | `continue_activity` 또는 `ask/request_hint` |
| 9 | Agenda 발화 조건 충족 | `ask/resume_puzzle` |
| 10 | 그 외 | `listen` 또는 `ignore` |

동일 상대·같은 종류의 사회적 발언에 대한 acknowledgement는 15초에 한 번 이하로 제한한다. 읽고 작은 감정 변화가 있어도 매번 응답할 필요는 없다. 감정 자극 증가량이 0이라는 이유만으로 `ignore`하지 않는다. 유효한 사회적 발언이고 응답 제한이 풀렸다면 기존 감정·기분에 따른 응답을 계획할 수 있다. 입력 유효성·대상·불확실성 판단과 상위 행동 우선순위는 계속 적용한다.

명확한 질문도 반드시 발화한다는 기존 규칙은 §10.1로 대체한다. 출력 자원 부재·공급자 오류는 의도적 침묵의 근거가 아니며 무한 대기시키지 않고 Runtime의 실패·만료 정책을 따른다.

### 10.1 선택적 발화와 침묵 이유 — 구현 계약

**처리 순서:** 주의에서 선택한 입력의 의미를 해석하고 필요한 상태·관측 효과를 적용한 뒤, Core가 발화 또는 의도적 침묵을 선택한다. 의미 해석의 불확실성 보류, 입력 미선택, 오류·취소·출력 자원 대기와 의도적 침묵을 구분한다. 기존 `listen`/`ignore`를 모두 새 기능의 성공으로 재분류하지 않는다. **2026-10-21 사용자 결정:** 의미 해석이 불확실하면 감정 변화만 보류하고 대답은 한다(질문은 되묻기). 불확실한 행위 분류로는 반복 제한을 걸지 않는다. 기술 실패·검증 실패의 보류와 확실한 직접 공격의 의도적 침묵은 유지한다. **2026-10-22 사용자 결정:** 판정 공급자(Jev 등)의 호출 실패·검증 실패·하루 호출 상한 도달도 침묵이 아니라 사회적 행위·감정 없이 일반 대답(`purpose:'other'`)을 한다. 판정 공급자는 감정에만 영향을 준다. **2026-10-22:** 침묵 이유 질문·듣기 요청은 문구 정규식이 아니라 검증된 Jev 대화 판정(`jev-conversation-v1`의 conversation_act)으로만 인식한다. 평가 대상(target)은 발화 상대와 다르므로 대화 행위의 조건이 아니다.

발화 선택은 대상·대화 흐름·이미 답한 내용·현재 감정·활동을 근거로 한다. 직접 질문과 재차 건넨 말은 강한 참여 이유이며 자동 발화 명령은 아니다. 감정 증가량 0, `other` 분류, 무작위 비율만으로 침묵을 정하지 않는다. 새 재접근 질문은 앞선 칭찬·비난의 15초 반복 제한으로 막지 않는다. 침묵은 다음 입력을 잠그거나 자기 대사를 반복해서 생성하는 상태가 아니다.

**기록의 최소 의미와 소유권:** Core가 선택하고 Store가 기존 상태 전이와 같은 트랜잭션에 저장한다. `Plan.participation`은 speak/silent/defer를 구분한다. 대사 모델은 기록을 읽어 표현하며 이유·감정 원본을 쓰지 않는다. 별도 DB 컬럼·wire 메시지는 추가하지 않았다.

| 기록 | 필요한 의미 |
|---|---|
| 선택과 시점 | 발화/의도적 침묵의 결정, 선택 사건과 평가 시각·state version |
| 대상과 근거 | 상대 ID, 관측한 입력 및 관련 원인 event/revision·memory/content version 참조. 입력 원문 복제 금지 |
| 당시 이유와 상태 | 듣기, 덧붙일 말 없음, 불편해 대꾸를 삼감 등 선택 시 확인 가능한 간단한 이유와 최소 감정 요약. 장문의 사고 과정·사후 추측 금지 |
| 이후 공개 정도 | 새 입력에서 현재 상태와 함께 설명·일부 공개·설명 회피·재참여 또는 계속 침묵을 선택. 당시 이유를 덮어쓰지 않음 |

최근 이유는 strict State schema의 `turn.recentSilences`에 상대별 최근 1건, 캐릭터 전체 최대 20건으로 보관한다. 같은 상대의 새 의도적 침묵으로 교체하고 상한을 넘으면 가장 오래된 기록을 제거한다. `eventId/eventRevision/stateVersion/identityId/at/reason/sourceRefs/affect`를 저장하며 원문은 복제하지 않는다. 이전 snapshot의 누락 필드는 빈 배열로 읽고 기존 DB CHECK와 호환되므로 migration을 추가하지 않았다. 유효 기록은 세션 전환·재시작 뒤에도 복구하되 감정은 경과 시간에 따라 갱신하고 출력은 자동 재생하지 않는다. 기록 보유 자체는 계속 침묵할 이유가 아니며, 과거 기록이 현재 대화와 연결되지 않으면 현재 이유로 단정하지 않는다.

**현재 선택 정책:** target=character인 명시적 듣기 요청과 침묵 이유 질문은 감정 평가와 참여 근거를 분리한다. 전체 appraisal이 확실하거나, 유효한 Jev 결과의 target·act가 각각 기존 0.8 이상·유일 최빈값이며 현재 appraisal과 일치하면 해당 명시적 요청을 처리한다. 감정 평가의 uncertain·강도 0은 그대로 보존한다. 인용·대상 불명·낮은 대상/행위 확신·동률·공급자 오류는 이 경로를 허용하지 않는다. Store가 검증한 좁은 근거를 Core에 전달하며 원문만 보고 Jev 판단을 덮어쓰지 않는다. Jev v6의 검증된 대상·행위 근거는 별도의 acknowledgePraise 권한으로 불확실한 칭찬에도 응답할 수 있게 한다. 감정 하한이 0이어도 참여는 가능하며 기존15초 응답 제한과 no_addition 이유는 유지한다. 구형 v4의 참여 근거에는 이 새 권한이 없다.

명시적 듣기 요청은 listening, 감정 평가까지 확실한 criticism/hostility=3은 withholding, 기존 사회적 발언의 15초 반복 제한은 no_addition 이유로 선택한다. 재접근에서는 같은 상대의 유효한 당시 기록을 설명·일부 공개·회피에 사용하고 없거나 무효하면 unknown으로 처리한다. 반복 사유에는 앞선 acknowledgement의 유효 출처가 필요하다. 해당 출처가 없거나 최근 출력 실패·취소·보류가 있으면 제한은 유지하되 defer로 처리하고 새 침묵 이유를 만들지 않는다. `other` 분류만으로 침묵하지 않으며 나머지 불확실성은 확인 질문 또는 defer로 구분한다. 걱정·재촉·배려 같은 숨은 의도를 임의 추론하지 않는다.

**다시 말을 걸었을 때:** 같은 상대를 향한 명시적 침묵 질문과 유효 기록에서 `Plan.reengagement`를 만든다. withholding 기록은 현재 frustration 0.60 이상이면 기존대로 deflect다. 불편함 공개 구간은0.20에서 진입한다. 같은 유효 기록에0.20 이상이 저장됐고 연결된 현재 원인이 남아 있으면0.10 미만으로 식을 때까지 구간을 유지한다. 이 구간의 기본은 partial, 밖에서는 explain이며 다른 이유는 explain이다. 표시 표정이 이 선택을 결정하지 않는다. 2026-10-15 후속으로 이 불편함 공개 구간에서 같은 이유를 이미 설명하도록 계획해 정상 전달했고 그 침묵 사건 또는 기록에 연결된 같은 상대의 원인이 현재 감정에 남아 있으면 deflect를 선택할 수 있게 했다. Store가 검증한 최근4교환 안에 같은 상대·같은 silence event의 완료된 explain/partial 응답이 있어야 하며, 현재 사과·대상 정정이 포함된 질문에는 이 새 경로를 적용하지 않는다. 새 withholding 기록에는 같은 상대에게서 남은 frustration 원인의 활성 관측 event/revision을 기존 sourceRefs 한도40 안에서 함께 결합한다. 최신 사건의 추가 자극이0이어도 이전 원인과 감정은 보존하며,0인 사건을 affect.causes에 새 감정 원인으로 넣지는 않는다. 듣기·다른 상대·임의 기억은 이 감정 연결 대상이 아니다. 연결된 출처가 삭제·변경되면 기존 출처 검증과 응답 무효화를 따른다. 기존 저장 기록에 출처를 소급 보충하지 않는다. 대사 문구나 반복 질문 횟수만으로 설명 완료·공격·상대의 이해를 추측하지 않는다. 과거 계획과 전달 완료는 확인하지만 대사 의미의 정확성은 별도 생성 품질 검증 대상이다.

**2026-10-15 공개 의사 분리:** 위 감정 구간은 기본 경로다. 별도로 검증된 의미 기반 이유 질문에서 같은 세션·상대의 최근4교환에 해당 withholding 입력이 있고 침묵 후10분 이내이면, 감정 수치와 무관하게 첫 질문에 partial을 선택한다(기존 frustration≥.6의 deflect는 유지). Store가 출처와 revision을 검증한 사건 ID만 사용한다. 같은 사건의 explain/partial이 최근 문맥에서 정상 전달됐고 현재 사과·대상 정정이 모두 no이면 재질문에 deflect를 선택한다. yes/unknown이면 새 회피 권한을 주지 않는다. 이 선택은 불편함이 .1 아래로 줄어도 최근 문맥·기간 안에서 이어질 수 있다. 문맥에서 해당 침묵 입력이 빠지거나10분을 넘으면 이 경로는 끝나고 기존 감정 구간을 따른다. 강도 unknown을 감정 증가로 바꾸지 않는다. 당시 frustration=0인 기록을 설명할 때는 불편함을 사실로 단정하지 않고 당시 대꾸하지 않기로 한 선택만 전달한다. [설계·성공 기준](../plans/DISCLOSURE_CONTEXT_PLAN.md)을 따른다.

기록이 없거나 삭제됐거나 최근 출력 실패·취소·보류가 있으면 unknown으로 전달한다. 인용·제삼자 대상에 자신의 이유를 적용하지 않는다. 수치와10분은 공개 정도 선택의 제품 규칙이며 감정 계산이나 심리학적 측정값이 아니다. “듣고 있었어” 또는 회피하는 “몰라”는 표현 예시이며 고정 대본이 아니다. 재접근은 감정을 초기화하거나 원인을 새로 만들어내는 명령이 아니다. 주제 전환은 유효한 최근 설명을 지우지 않지만, 문맥에서 빠졌거나 설명 출처가 정정·삭제된 경우 새 deflect 권한으로 쓰지 않는다. 의존 응답이 이미 준비 중이면 기존 source-response 무효화 경계를 적용한다. 새 DB 컬럼·wire·장기 marker는 추가하지 않았다.

**출처와 종료:** 이유에 쓰인 근거를 정정·삭제하면 관련 기록·전이의 민감 내용과 후속 생성 context에도 기존 무효화/삭제 정책을 적용한다. 다른 상대의 이유를 가져오지 않는다. 의도적 침묵은 필요한 상태·선택 기록만 commit하고 response/segment·빈 자막·완료 ACK 대기를 만들지 않는다. 발화를 선택한 뒤 생긴 오류·형식 거부·취소를 침묵으로 바꾸지 않는다. 다음 입력 처리는 정상적으로 가능해야 한다. 검증은 [ER09–ER11](../plans/VALIDATION_PLAN.md)을 따른다.

### 10.2 화제 전환과 재참여 뒤의 감정 지속 — 승인된 보강 계약

2026-10-11 사용자 승인 후 기존 affect/mood와 시간 규칙을 재사용해 구현했다. Core와 실제 합성 DB/출력 보고 경로에서 상태 지속을 검사했다. 실제 대사 품질은 상태 검사의 PASS와 구분한다.

- **상태의 연속성:** A에서 B로 화제가 바뀌어도 이전의 지속 감정·기분에서 시간 경과와 새로 채택된 사건의 효과를 적용한다. 화제 변경, 발화 재개, 이유 설명, 출력 완료만으로 감정을 초기값으로 되돌리거나 별도 회복 효과를 주지 않는다. 감정 효과가 없는 B 입력의 감정·기분 값은 기존 상태에 같은 경과 시간의 decay를 적용한 값과 일치해야 한다.
- **참여와 회복의 구분:** 다시 대답할 수 있다는 선택은 감정이 해소됐다는 판정이 아니다. 불편함이 남아도 다른 이야기에 참여할 수 있으며, 회복되지 않았다는 이유로 계속 침묵하게 만들지 않는다. 새 사건의 의미가 실제로 감정에 영향을 주면 그 해석·출처와 기존 상태 규칙에 따라 변화할 수 있다. 사과·배려·관심사라는 단어 하나나 대화 재개 자체로 회복을 확정하지 않는다.
- **표현의 연속성과 조절:** 현재 B의 목적·사실·대상을 유지하면서 이전 감정을 말투·길이·참여 의지에 반영한다. 표현을 누그러뜨리거나 설명을 회피해도 내부 감정을 덮어쓰지 않는다. 매번 A의 원인을 설명하거나 A로 화제를 강제로 돌릴 필요는 없다. 특정 상대에 대한 원인·책임을 다른 상대에게 옮기지 않는다.
- **감정 숨김:** 내부 감정과 겉표현의 일치를 강제하지 않는다. 이유 비공개와 감정 표현은 별도 선택이며, 새 Plan의 격식·긍정 호응은 §11을 따른다. 감정 자체를 감추기로 했다면 평소 말투로 표현할 수 있다. “이제 괜찮아”라는 대사만으로 실제 감정 회복이나 품질 실패를 판정하지 않는다. 사전에 정한 공개 정도와 맥락을 비교하고, 출력 뒤 감정 수치가 초기화되지 않았는지는 따로 검사한다. 감정 차이가 보이지 않는 실패를 사후에 숨김 의도로 합리화하지 않는다.
- **이유 기록과 감정 수명:** §10.1의 당시 요약은 과거 선택의 근거이며 현재 affect/mood의 원본이 아니다. 기록 교체·상한 초과·출처 삭제로 이유가 없어져도 현재 감정을 초기화하지 않는다. 남은 이유를 조회하거나 복구했다고 과거 감정을 재자극하거나 당시 값으로 되돌리지 않는다. 삭제된 원인 참조·민감 내용은 제거하고 현재 감정은 기존 감쇠 규칙을 따른다.

이 구분은 논리적 책임 분리이며 새 topic별 감정 저장소·회복 여부 flag·주제 분류 모델을 요구하지 않는다. Core가 지속 상태를 소유하고 생성 모델·Stage가 대사나 표정에서 회복 여부를 역으로 써 넣지 않는다. 검증은 ER01/ER02/ER10과 [ER12](../plans/VALIDATION_PLAN.md)를 따른다.

## 11. 표정과 발화 계획

내부 감정에서 다음 표현 점수를 계산한다.

```text
happy_score = 0.8 × joy
uncomfortable_score = 0.5 × frustration
embarrassed_score = 0.7 × embarrassment
```

점수 0.10 이상 중 가장 큰 표현을 고르고, 없으면 neutral이다. 동률은 embarrassed → uncomfortable → happy 순서로 고정한다. 현재 표현은 점수가 0.05 미만이 되면 neutral로 내려갈 수 있다. 다른 표현으로 바꾸려면 새 점수가 현재 점수보다 0.03 이상 높고 최소 2초 유지 시간이 지나야 한다.

이 유지 시간은 사용자 발화 시작에 따른 listening 표시와 출력 취소를 막지 않는다. listening은 대화 차례에 따른 우선 표시이며 기존 감정을 삭제하지 않는다. surprise는 새 퍼즐의 가벼운 고개·시선 동작으로 표현하고 여섯 번째 기본 표정을 추가하지 않는다.

frustration 또는 embarrassment가 0.60 이상이면 최대 한 문장과 짧은 휴지를 요청한다. 그 밖에는 최대 두 문장, 한국어 기준 목표 80자·총 120자 이내로 생성한다. 일반 재접근 대사는 2026-10-11 이유 충실성 수정에 따라 더 좁은 한 문장 상한을 적용한다. 유효한 저장 이유·공개 방침·현재 말투를 분리하고 과거 원문 지시는 다시 전달하지 않는다. 이유 부재는 원인에 대한 정보 부재이며 사건 부재나 모든 기억 부재가 아니다. 현재 validator는 문장 수·길이 등 형식 위반을 `invalid_output` 실패로 처리하고 출력하지 않는다. 자동 절단·재구성·대체 대사로 통과시키지 않는다.

기분이 0.45 미만이면 차분한 전달, 0.65 초과면 약간 활기 있는 전달을 계획한다. 이 범위 안에서는 기본 전달이다. 아래 speechStyle이 없는 구형 Plan의 생성 지침은 기존 expression/delivery와 재접근 공개 방침을 따른다. 새 Plan의 한국어 말투는 speechStyle의 독립된 두 선택을 우선한다. 어느 경로도 내부 기분을 회복시키지 않는다. TTS 속도·pitch를 임의로 크게 변경하지 않고 지원되는 표현 범위에서만 적용한다.

<a id="speech-style-contract-20261016"></a>
**CX 후속 로컬 구현:** 실제 계약은 `packages/contracts/src/domain.ts`의 `SpeechStyle`이다. 선택 필드 `discomfortTone?: 'contextual'|'sharp'|'restrained'|'masked'`를 추가했다. contextual은 맥락에 맞는 날 선 표현 또는 차분한 거리 두기 선택, sharp는 날 선 표현 의도, restrained는 차분한 경계, masked는 불편함만 숨김이다. 표현 선택이며 새 감정·관계 증거가 아니다. 필드가 없는 구형 Plan에는 새 공격 표현을 강제하지 않는다. 전체 concealAffect가 최우선이다. [BUILD 증거와 실제 검증 한계](../plans/OUTCOME_AFFECT_PLAN.md#contextual-expression-build-20261017)를 따른다.

**2026-10-16 구현 계약, 감사 수정1과 실제 표현 후속 반영:** 선택 필드 `Plan.speechStyle?: {register:'casual'|'formal'; positiveTone:'neutral'|'warm'|'bright'; nuance?:'cautious'; concealAffect?:true}`를 저장 계획과 생성 지침에 연결했다. §6의 독립 affect와 원인 보존, 표정 enum, Stage wire, 감정 저장 schema는 유지한다. 표정의 최고 점수나 joy-frustration 차이, pleasantness만으로 격식과 긍정 호응을 정하지 않는다. `nuance`는 기존 당황 표현을 보존하는 출력 선택이며 새 감정 축이 아니다. 필드가 없는 구형 Plan은 이전 생성 경로로 처리하며 과거 기록에 소급 추가하지 않는다. [검증 결과](../results/MIXED_AFFECT_EXPRESSION_RESULT.md#cautious-live-20261016)는 현재 소스의 실제 발화4·ACK8과 직전 구조 수정414건·초기 Stage12입력의 범위를 구분한다. 추천 질문의 긍정 호응과 풍부한 혼합 표현은 제한적으로 남고, 강한 복합 감정의 자연 도달·제작자 수용은 미확인이다.

- **Core 선택:** joy의 neutral/warm/bright 경계는 기존 .05/.6을 유지한다. 같은 상대의 원인이 있고 frustration≥.1인 공개 거리 두기의 기본은 formal+contextual이다. 신뢰된 명시적 sharp/restrained 의도는 casual로도 표현할 수 있다. 부분 숨김은 유효한 원인이 있고 frustration≥.05일 때 masked로 기록하며 전체 숨김은 concealAffect다. 같은 만남·상대에게 마지막으로 완료 전달한 거리 표현이 현재 유효한 원인을 공유하면 formal 또는 casual 격식을 frustration≥.05 동안 이어 간다. casual은 날 선/차분한/부분 숨김 표지 또는 전체 숨김이 있는 이전 Plan만 지속 대상으로 삼는다. 회복 구간에서 공개 casual은 restrained로 이어 가고 .05 미만이면 표지를 해제한다. 실패/미전달 출력·다른 상대·다른 만남은 이어받지 않는다. 새 원인이 생긴 뒤의 재진입을 막지 않으며 감정 값·원인은 바꾸지 않는다. 이 값은 구현 구간이며 심리학적 최적값의 주장이 아니다.
- **Store 근거:** formal·discomfortTone 또는 전체 숨김의 원인 의존성을 저장하기 전에 같은 캐릭터의 활성·관찰된 원본 사건, accepted appraisal의 정확한 event revision, 직접 비난 transition과 양수 자극, 원인의 targetId와 원본 identity의 일치를 확인한다. 근거가 없으면 register를 casual로 낮추고 discomfortTone을 제거한다. 전체 숨김이면 discomfortTone을 제거하되 유효한 기존 격식은 유지한다. 유효한 casual 거리 표현도 response_sources에 연결해 출처 수명 검사를 공유한다. O1 사건의 불편함을 직접 비난으로 간주하지 않는다. 긍정 호응은 현재 joy 값으로 정하며 원인별 강도를 역산하지 않는다.
- **공개 투영:** 전체 숨김·silent/defer·비발화는 neutral이 우선이다. 그 밖에는 cautious→embarrassed, 불편함을 숨기지 않은 formal 또는 공개 discomfortTone(contextual/sharp/restrained)→uncomfortable, warm/bright→happy, 나머지→neutral이다. masked는 유지된 formal보다 우선하므로 존댓말을 유지해도 불편 표정을 노출하지 않는다. 공개된 기쁨·조심스러움은 별도로 표시하고 전체 은폐는 concealAffect로 구별한다. 이 우선순위는 [10월18일 감사 수정](../plans/OUTCOME_AFFECT_PLAN.md#contextual-expression-audit-20261018)에서 회귀·실제 Chrome 대조로 확인했다. 기존 Stage wire와 내부 expression은 바꾸지 않는다.
- **생성 초안과 표현:** content-first 요청의 `content`는 사실·응답 목적의 중립 메모이며 대사·감정 판단·공개 권한이 아니다. 기존 `speechStyle`을 요청의 `surface`에 전달하고, 최종 `sentences`는 초안의 어미·감정 평가를 복사하지 않고 격식·숨김을 적용한다. 부분 숨김에서도 직접 묻는 사건 사실은 답할 수 있으나 자기 불편함의 평가·조건부 수용이나 묻지 않은 원인 요약을 추가하지 않는다. 사실 확인 답변을 상대에게 확인 행동을 요구하는 말로 뒤집지 않는다. 한 호출의 요청 계약이며 의미 준수를 강제하는 decoder 검사는 아니다. [후속 검증](../plans/OUTCOME_AFFECT_PLAN.md#contextual-expression-surface-20261018)에서 실제 수행 여부를 별도로 판정한다.
- **출처 수명과 비공개:** 실제 사용하는 유효 거리 원인과 긍정 원인을 response_sources의 revision 의존성으로 연결한다. 사회적 긍정 원인은 accepted appraisal의 정확한 revision과 praise 자극을 확인한다. 활동 기쁨은 활성 정답 단계·사용 가능한 transition·문제 일치·기존 activity_result의 원본 출처 revision을 확인한다. targetId가 문제 ID이면 정답 사건, 도움 준 상대이면 같은 정답 사건과 support_group으로 연결된 활성 verified_hint 근거의 정확한 출처들을 등록한다. 활동 사건의 null identity를 상대 ID와 비교하지 않는다. 이 의존성만을 이유로 과거 발언이나 활동 원문을 생성기의 sources에 추가하지 않는다. 현재 trigger와 직접 부모, 현재 입력·정당한 대화 이력·별도로 허용된 침묵 이유는 기존 경로로 전달한다. 삭제는 기존 계획 무효화와 epoch 취소를, revision 불일치는 늦은 생성의 출처 검사를 따른다.
- **당황 보존과 감정별 숨김:** Core는 기존 expression이 embarrassed이며 당황을 감추지 않을 때 `nuance:'cautious'`를 선택한다. 생성기는 격식·긍정 호응을 유지하며 조심스럽게 말하고 없는 실수·원인이나 감정 해설을 붙이지 않는다. 순수 정책 함수는 joy/discomfort/embarrassment의 show/mask를 받는다. 기쁨 mask는 positiveTone을 neutral, 불편함 mask는 새 formal 진입을 억제하고 당황 mask는 nuance를 생략한다. 기존에 전달한 formal은 위 지속 규칙으로 유지할 수 있으며 mask만으로 casual 복귀를 강제하지 않는다. 세 mask를 함께 적용하면 concealAffect:true로 Stage 공개 표정을 neutral로 투영한다. 내부 감정은 보존한다. 운영에서는 이유 질문의 deflect이면서 frustration≥.6인 기존 강한 감정 숨김 경로에 세 mask를 적용한다. 그 밖의 이유 비공개는 formal·긍정 호응·당황의 조심스러움을 유지할 수 있다. 모든 숨김 조합을 자연 대화에서 선택한다고 주장하지 않는다. C6의 불편함만 숨김은 평가 도구가 사전에 넣는 통제 의도다.

생성기는 [캐릭터 표현 계약](../product/CHARACTER_PRESET.md#mixed-affect-expression-20261016)의 격식과 긍정 호응을 함께 표현한다. 이유를 숨기는 선택을 기억 부재로 바꾸거나 고마움을 완전한 화해 선언으로 바꾸지 않는다. 고정 예문을 사후 치환하지 않으며 기존 문장 수·길이·사실·참여 경계를 유지한다. 표현 선택만으로 내부 감정을 초기화하지 않는다.

실제 후속에서 cautious+formal+bright가 격식만 남기는 경우를 확인해, 해당 조합에만 조심스러운 말머리·긍정 호응을 함께 표현하도록 생성 지침을 보완했다. 내부 상태와 선택 정책은 바꾸지 않는다. 이는 당시 지침 변경 범위다. 이후 Stage 공개 표시를 분리했고, 현재 전체 감정 숨김에서는 유지된 formal과 별개로 neutral을 표시한다. [말투 지속 결과](../results/REGISTER_CONTINUITY_RESULT.md)를 따른다.

발화 계획에는 action, purpose, target ID, 감정 요약, 사용 가능한 기억 ID, 길이와 표현 제약을 넣는다. 숫자 상태는 UI에서 볼 수 있지만 캐릭터가 설명하지 않는다.

§10.2에 따라 새 화제의 plan에도 이어진 현재 상태가 반영돼야 한다. 표정 변경·발화 재개·전달 완료를 감정 회복 사건으로 역복사하지 않는다. 표정이 listening/neutral이거나 말투가 차분하다는 사실만으로 내부 affect/mood를 초기화하지 않는다.

## 12. 사건 기억과 검색

### 12.1 무엇을 기억하는가

필수 저장 대상은 활동 결과, 사용한 힌트와 상대, 명시적인 미완료 활동, 실제 전달된 제안과 수락·거절이다. 평범한 인사·반복 칭찬·미관측 채팅은 자동으로 장기 기억에 올리지 않는다. 관측한 일반 대화는 작업 기억과 운영 기록으로 충분하다.

사건 기억의 사실 부분은 초기에 구조화 이벤트에서 템플릿으로 만든다. 예를 들어 “A의 힌트가 사용된 뒤 문제 P를 해결했다”를 보존한다. 이것을 “A는 항상 정확하다”로 일반화하지 않는다.

LLM이 표현을 다듬더라도 원본의 참여자·활동 ID·결과를 바꾸지 못한다. 기억마다 출처와 `observed/reported/inferred` 구분을 남기며, MVP의 행동 근거는 관측된 활동 사실을 우선한다. 모델의 자기 confidence 숫자로 출처가 약한 기억을 강한 기억으로 승격하지 않는다.

### 12.2 검색 규칙

1. 캐릭터·공개 범위·유효 상태를 먼저 필터링한다.
2. 현재 활동의 미완료 기억을 우선한다.
3. 같은 상대의 활동 근거를 찾는다.
4. 관련 최근 사건을 더하되 같은 활동의 중복 기억은 합친다.
5. 관련성 동률에서는 최근 사건, 그다음 ID 순서로 고정한다.

최대 5개, 기억 부분 최대 600 tokens를 목표로 한다. 정확한 토큰 계수는 모델 연결 계층에서 처리한다. 예산 초과 시 낮은 우선순위 기억 전체를 제외하고 출처나 문장을 중간에서 잘라 뜻을 바꾸지 않는다.

검색 결과가 없으면 과거 대화를 생성하지 않는다. B와 대화하며 A의 공개 사건을 언급할 수는 있으나 공유 경험의 주체는 계속 A다.

세션 종료 정리는 기존 사건을 묶고 미완료 의도를 정리한다. 이미 적용된 감정·호감·신뢰를 다시 갱신하지 않는다. 의미 일반화·성격 변화는 하지 않는다.

## 13. Agenda 1종: 미완료 퍼즐 이어가기

종류는 `resume_puzzle` 하나다. 세션 종료 시 실제로 미완료인 활동이 있고 사용자가 명시적으로 종료·거절하지 않았다면 후보를 하나 만든다. 이미 해결된 퍼즐을 미완료라고 말하지 않는다. 새 문제 제안은 현재 세션의 활동 선택으로 처리하며 경험 기반 Agenda 종류를 추가하지 않는다.

발화 조건을 모두 만족해야 한다.

- 다음 세션이 시작된 지 30초 이상.
- 현재 사용자 발화, 활성 응답, 풀이 작업, 처리할 질문이 없음.
- 마지막 사용자 입력 또는 출력 종료 중 더 늦은 시점부터 8초 이상 지남.
- 관련 참여자 중 적어도 한 명이 현재 세션에서 관측됨.
- 원본 활동·기억이 유효하고 생성 후 7일 이내.
- 이 세션의 자발적 제안 시도 예산이 남아 있음.

제안 시도 예산은 세션당 1이다. 발화 계획을 commit할 때 예약·소진한다. 재생이 취소되거나 실패해도 같은 세션에서 자동 재시도하지 않는다. 재시작으로 같은 session ID의 예산이 복구되지 않는다.

상태는 pending → reserved → offered → accepted/declined/expired다. 전달에 실패한 reserved는 미전달로 기록하고, 활동과 원래 7일 기한이 유효하면 다음 세션에만 다시 후보가 될 수 있다. 완성된 제안이 실제 전달되기 전에는 offered로 만들지 않는다.

확실히 미전달된 예약은 pending으로 돌리되 `last_attempt_session_id`를 남긴다. 실제 전달 여부가 불명확하면 만료 처리하고 자동 재제안하지 않는다. offered 뒤 60초 동안 수락·거절이 없으면 expired로 끝낸다. declined 또는 expired가 된 동일 근거의 Agenda를 종료 정리에서 다시 만들지 않는다.

명확한 수락은 활동을 재개하고 Agenda를 accepted로 종료한다. 명확한 거절은 declined로 종료하며 다음 세션에도 같은 근거로 자동 재생성하지 않는다. 직접 “그 문제 다시 하자”라는 새 요청은 사용자의 명시적 행동으로 재개할 수 있다. 무응답·애매한 답은 관계 변화 없이 제안을 끝내고 추가 독촉하지 않는다.

## 14. 실제 출력, 정정, 재시작

### 14.1 내가 한 말의 기준

LLM 생성 완료와 TTS 합성 완료는 전달 완료가 아니다. 활성 Stage가 완료를 보고한 문장은 `delivered_audio`, 화면에 표시 완료된 자막은 `delivered_text`로 구분한다. 사람이 실제 들었는지까지 안다고 주장하지 않는다.

중간에 끊긴 문장은 일부 전달됨으로 남긴다. 정확한 단어 위치를 알 수 없으면 전체 문장을 했다고 기억하지 않는다. 이미 전달한 앞 문장은 유지하지만 생성만 한 뒤 문장은 다음 대화의 확정 발언 이력에서 제외한다.

### 14.2 정정·삭제

정정·삭제된 근거는 검색·Agenda·힌트 요청 대상 선택에서 즉시 제외한다. 그것에 의존한 관계 근거를 무효화하고, 유효한 근거를 시간 순서로 다시 적용해 친숙함·호감·신뢰 목록을 계산한다. 일일 상한도 같은 시간 순서로 다시 계산한다.

기억 삭제와 원본 사건 삭제를 구분한다. 기억만 삭제했다면 그 기억에서 파생된 제안·해석은 제거하지만, 독립된 유효한 원본 사건까지 자동으로 거짓으로 만들지 않는다. 원본 관측 자체가 정정·삭제됐다면 거기에 의존한 관계 근거와 다른 기억도 함께 무효화한다. 삭제한 기억은 같은 출처와 내용으로 다음 정리 작업에서 자동 재생성하지 않는다.

현재 출력 계획이 해당 기억을 참조하면 취소한다. 현재 감정의 삭제된 원인·상대 참조는 제거한다. 이미 생긴 감정의 숫자는 새로운 자극 없이 시간에 따라 감쇠시키며, 과거 발화나 감정이 없었던 것처럼 소급해서 꾸미지 않는다.

### 14.3 재시작

최신 commit 상태를 읽고 감정·기분에 경과 시간을 적용한다. 진행 중 입력 해석·풀이·출력은 중단 상태로 기록하고 자동으로 다시 말하지 않는다. 저장된 미완료 퍼즐은 남기되 직접 요청 또는 유효한 Agenda로 재개한다.

### C2-S2 계산 경계 보강 — 2026-10-13

선택적 verifyRepetition으로 검증한 구체적 직접 칭찬만 그룹 선택 후보가 된다. Store는 같은 상대의600초 전체 유효 출처와 저장 label을 재검증한다. Core의 selectPraiseGroup은 이전0개 또는 모두 distinct이면 새 label 요청, 정확히 한 그룹의 모든 구성원이 same이고 나머지가 distinct이면 기존 label을 선택한다. 불완전·미분류·unknown·충돌이면 전체 범위로 계산한다. UUID는 Store만 생성하고 모델이나 Core는 생성하지 않는다.

선택된 label이 있으면 socialAffect는 같은 label과 미분류 이력만 합산한다. cap0.30과 기존 시간 가중치는 유지한다. 관계 v1, 공격,15초 발화 제한, 숨김·침묵 이유·재참여는 바꾸지 않는다. 성취가 달라도15초 안의 칭찬은 no_addition일 수 있다. 모델 후보의 의미 검증 미달로 운영 v6에서는 label 선택 없이 기존 계산을 사용한다.

## 16. 대화 문맥·대화 행위·수선 — 2026-10-13 계획

**상태: 2026-10-14 행위·회복 구현 및 v2 로컬 검증 완료, 실제 v2 품질 미검증.** 제안 원본은 [IMPLEMENTATION_PLAN §20.3–20.5](../plans/IMPLEMENTATION_PLAN.md#conversation-redesign-v1), 현재 증거는 [v2 결과](../results/INTERACTION_V2_RESULT.md)다. 운영 Jev는 유지하며 새 후보는 평가용이다.

최근 문맥은 같은 캐릭터·상대·세션의 최대4교환/8메시지다. 실제 관측 사용자 발언과 완료 전달된 캐릭터 대사만 포함하고 현재 입력은 중복하지 않는다. 이전 대사는 발언 기록이지 외부 사실·사용자 동의·작업 수행의 증거가 아니다. 부분 전달의 기존 기록은 보존하지만 이번 첫 문맥 계약에서는 해당 assistant 응답 전체를 제외한다. 새로운 장기 회상 기능이나 미관측 입력의 공동 경험화는 없다.

감정 해석, 대화 행위, 공개 의도는 서로 다른 판단이다. v1 ConversationEvidence의 단일 act는 호환 유지하고 v2는 이유 질문·듣기·사과·대상 정정을 독립 yes/no/unknown으로 전달한다. 현재 speaker/recipient는 입력 경로에서 제공한다. 수선 대상·직접 공격/칭찬·일반 발화 형태를 각각 검증하며 세부 강도 불확실성이 확인된 행위를 지우지 않는다. 감정 권한은 별도 하한 근거이고 관계 계산은 바꾸지 않는다. provider raw는 adapter만 해석하고 Core에는 출처 검증된 공급자 중립 값만 전달한다. 엄격 verifier의 출처 실패/공급자 오류는 Store가 중립화해 기술적 보류로 처리한다.

v2 우선순위는 현재 공격→듣기→이유 설명→수선 시도다. 불명확한 듣기/공격은 수선 권한을 주지 않으며 이유 질문이 겹쳐도 설명 자체로 수선하지 않는다. 칭찬+새 질문은 질문을 우선하고 일반 반복 칭찬/인사의 no_addition은 유지한다. 의도적 침묵, 확인 질문, 기술적 보류를 정상 응답과 따로 평가한다.

선택형 Decisions v5는 공급자 중립 `responsePressure`(yes/no/unknown)를 추가한다. 옛 근거에서 이 항목이 없으면 압박 권한이 없다. 현재 상대의 위협·윽박지름·복종을 재촉하는 응답 요구를 판단하며 욕설이나 명시적 협박이 필수는 아니다. 정중한 재촉·단순한 긴급 요청·인용·타인 대상·평범한 이유 질문과 구분한다. 판정 문턱은 yes≥.95/no≤.05이며 압박 자체는 감정 증가나 관계 변화의 근거가 아니다.

확인된 압박과 같은 상대의 유효한 withholding 기록이 함께 있으면 위 우선순위보다 먼저 경계 표현을 선택할 수 있다. 불편함≥.6 또는 검증된 최근4교환 문맥에 완료 전달된 `set_boundary` 응답이 있으면 withholding을 유지한다. 그렇지 않으면 당시 침묵 이유를 숨긴 채 한 문장으로 강요를 거절한다. 이 발화는 순응·사과·보복이나 감정 회복이 아니며, 직접 공격의 감정 효과는 별도 기존 경로를 따른다. 실패한 출력·다른 상대·삭제/무효 기록으로 이 권한을 만들지 않는다. 압박 yes/unknown과 함께 나온 사과는 수선 권한을 얻지 않는다. 최근 문맥에서 경계 발화가 빠진 뒤에는 다시 경계를 말할 수 있으며 영구 침묵 잠금을 추가하지 않는다.

일반 발화가 질문형인지 서술형인지 모른다는 사실은 답변에 필요한 대상이나 정보가 부족하다는 뜻이 아니다. v2에서 직접 공격·직접 칭찬과 네 대화 행위가 모두 no이고 speechAct만 unknown이면 일반 other 응답을 허용한다. 이 선택은 감정·수선·이유 공개 권한을 추가하지 않는다. 생성은 현재 내용에 답하되 대상이나 필요한 정보가 실제로 빠졌을 때 그 부분을 묻는다. 다른 의미 판단의 불확실성이나 공급자 오류는 기존 확인/기술 보류 규칙을 유지한다.

Core는 이유 질문을 알아들었어도 저장 이유의 존재와 현재 공개 선택으로 explain/partial/deflect/unknown을 고른다. 감정을 숨기는 담담한 표현을 표현 실패로 세지 않는다. 기록이 없거나 앞선 출력이 기술적으로 실패했으면 감정적 이유를 만들지 않는다. 이미 설명한 사실은 유지하되 대사 표현까지 고정하지 않는다.

사과/오해 해소는 인정하는 대사와 감정 변화가 다를 수 있다. 제한 회복 시범은 같은 상대·같은 세션의10분 이내 유효 직접 비난 후보, 현재 frustration 원인의 상대 일치, 미사용 marker를 모두 요구한다. 통과하면 decay 후 F에서 r=min(0.03,0.10×F)를 한 번 감하고 pleasantness에0.1×r을 더한다. 다른 affect·관계·hold·원인 참조는 그대로다. 여러 상대 원인이 섞이면 수치 변화0으로 보수적으로 유보한다. 이 수치는 제품 가설이며 검증된 심리 모델이 아니다.

새 화제·이유 설명·출력 완료·겉으로 괜찮다는 말은 회복 사건이 아니다. 수선 marker는 중복 처리·재시작·원문 정정/삭제로 다시 사용 가능해지지 않는다. 삭제된 사건을 원인으로 새 감정 변화나 설명을 만들지 않으며 기존 감정 값을 소급 재생하지 않는다. 검증 범위 밖인 여러 상대의 정밀 원인별 회복과 장기 관계 수선은 후속 과제로 남긴다.
