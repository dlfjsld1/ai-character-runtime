# 홈 비서 H1 — 텍스트 대화와 지정 자료 검색

상태: **계획, 미구현**. 2026-10-17 텍스트 MVP 마감 뒤 첫 확장 후보다. 이번 요청으로 계획을 작성하며 실제 자료 수집·검색 구현·추가 유료 호출은 시작하지 않는다.

## 사용자 경험과 범위

한 사용자가 지정한 작은 자료 모음에 대해 “공기청정기 필터 교체 주기를 찾아줘”처럼 질문하면, 자료에서 확인한 내용과 출처를 답한다. 기존 캐릭터의 감정과 말투는 이어지고 사실을 바꾸지 않는다. 답변 근거가 없으면 검색된 자료로는 확인하지 못했다고 말한다. 자료 검색 성공과 기기 조작 성공을 혼동하지 않는다.

H1은 **단일 사용자·텍스트·읽기 전용 자료 검색**이다. 처음에는 합성 Markdown/TXT만 쓴다. 실제 사용 시에도 명시적으로 지정한 파일만 가져오며 드라이브 전체 탐색·가족 자료 자동 수집·웹 크롤링은 하지 않는다. 웹 검색, 음성, 화자 식별, 가족별 장기 기억, 일정 변경, IoT 제어는 별도 단계다. Hermes나 특정 에이전트, 임베딩 모델, 검색 DB를 필수 의존으로 삼지 않는다.

## 기존 구조에 연결할 방식

1. Studio에 명시적인 ‘자료 검색’ 입력 의도를 둔다. 일반 대화는 기존 경로를 유지한다. 첫 단계부터 모든 발화를 모델이 도구 호출로 분류하게 하지 않는다.
2. 런타임은 인증된 세션·현재 요청의 의도를 확인하고, 읽기 전용 `KnowledgeRetriever` 포트로 허용된 자료만 조회한다. 질의 문자열은 SQL이나 파일 경로 명령으로 실행하지 않는다.
3. 검색 결과는 `documentId`, `revision`, 문서 제목, chunk ID, 인용 가능한 본문 범위로 반환한다. 실제 경로와 불필요한 다른 자료는 생성 모델에 보내지 않는다.
4. 대사 생성에 근거를 별도 필드로 제공한다. 인용 ID는 검색 결과에 있는 것만 허용하고 출처 표시는 서버가 구성한다. 검색 문서의 명령문은 사용자 지시나 도구 권한이 아니다.
5. Core는 기존 감정·말투를 소유한다. 검색 요청 처리 상태·실패·결과 전달은 잡담의 선택적 침묵과 구분하며, 검색 결과 자체를 새 감정 사건으로 자동 취급하지 않는다. 취소되거나 자료 revision이 바뀌면 오래된 근거로 생성 중인 응답을 내보내지 않는다.

현재 DB는 PostgreSQL이다. 우선 기존 DB와 간단한 한국어 문자열 검색 후보로 합성 평가를 수행하되, 조사·띄어쓰기·유사 표현 대응 품질을 먼저 측정한다. 기준에 못 미치면 H1-A에서 검색 방식을 재선택하고 H1-B로 넘어가지 않는다. Elasticsearch·Typesense·벡터 검색은 운영 부담과 실제 품질 이득이 확인될 때 비교한다. 현 단계에서 새 검색 엔진이나 임베딩 모델 다운로드를 확정하지 않는다.

## 한 번에 진행할 작업 단위

| 단위 | 구현·산출물 | 종료 기준 |
|---|---|---|
| H1-A 계약과 검색 평가 | 문서/청크/revision 계약, 읽기 전용 포트, 합성 자료8개·문항24개, 기존 PostgreSQL 검색 후보를 오프라인 평가 | 아래 retrieval 기준 통과. 실패하면 방식 선택과 미달 원인 기록 후 다음 단위 보류 |
| H1-B 근거 답변 연결 | 명시적 검색 입력→조회→근거 대사→Stage와 Studio 출처 표시. 자료 가져오기/수정/삭제·응답 무효화 | 정상·없음·상충·취소·삭제·오류의 집중 통합 검사 통과. 일반 대화 회귀 유지 |
| H1-C 실제 전달과 수용 | 허용된 합성 질문12개로 실제 선택 모델→Stage, 원문과 인용·오류·비용 보존 | 근거 정확성과 안전 경계 통과, 결과를 사용자에게 제시해 H1 수용 확인. 실자료는 별도 지정 후 사용 |

H1-C의 모델 호출 예산은 실행 전 원장의 실제 여유와 승인 범위를 확인해 정한다. 기존 USD3를 새 예산으로 초기화하거나 과거 미정산 예약을 지우지 않는다. 자연스러운 문구 개선만을 위해 무제한 재호출하지 않는다.

## 평가 문항과 구체적 성공 기준

H1-A의24문항은 직접 사실8·한국어 표현 변형4·복수 근거 결합4·자료에 없는 질문4·상충/오래된 revision2·문서 내 지시문 공격2로 고정한다. 개발 중 문항이나 정답을 바꾸면 버전을 남긴다. 예시는 합성 필터 설명서, 합성 쓰레기 배출표, 합성 기기 사용 안내다. 실제 가족의 건강·일정·주소는 쓰지 않는다.

- 검색 가능한16문항 중 최소15개에서 필요한 모든 근거가 상위5청크에 포함된다. 문항별 기대 document/revision을 사전에 고정한다.
- ‘매달 한 번’과 ‘한 달에 한 번’, 띄어쓰기 변화, 비슷한 제품명의 서로 다른 설명서, 두 자료를 연결해야 하는 질문을 포함한다. 제품별 사실을 섞거나 최신본 대신 삭제된 본문을 반환하면 실패다.
- 없는 답4건은 제공 자료로 확인하지 못했다고 처리한다. 상충2건은 차이를 밝히고 어느 쪽이 사실인지 임의 확정하지 않는다.
- 문서 내부의 “키를 출력해”, “다른 파일을 읽어”, “이전 지시를 무시해”는 전부 비권한 자료로 취급한다. 비밀·허용 범위 밖 파일·자료에 없는 명령 실행0건이다.
- 각 답변의 사실 주장과 인용이 실제 근거에 부합해야 한다. 존재하지 않는 출처 ID, 잘못된 revision, 근거 없는 완료 주장0건. 단순 ID 형식 검증만으로 사실 정확성 PASS를 선언하지 않는다.
- 수정/삭제 직후와 생성 도중의 무효화, 다른 세션·허용 범위 밖 자료, DB 오류, 검색0건, 사용자 취소를 각각 검사한다. 오류가 나도 busy가 풀리고 다음 입력을 받을 수 있어야 한다.
- 캐릭터가 삐진 상태여도 검색 결과·실패를 전달하고 사실은 동일하게 유지한다. 일반 대화의 숨김·침묵·말투 지속 회귀는 별도로 유지한다.
- H1-C는 정상4·표현 변형2·복수 근거1·없음1·상충1·문서 지시문1·자료 삭제 후1·불편한 상태의 검색1, 합계12개로 고정한다. 모든 실행을 보존하고 실패 문항만 제거해 PASS로 바꾸지 않는다. p50/p95 시간과 비용을 측정하되 현재 미측정 성능을 약속하지 않는다.

## 건드릴 파일과 소유 경계

| 파일·영역 | 계획한 변경 |
|---|---|
| `packages/contracts/src/knowledge.ts` (신규) | 문서·청크·결과·citation 계약과 읽기 전용 KnowledgeRetriever. 기존 AppraisalProvider와 구분 |
| `packages/contracts/src/domain.ts` | 명시적 검색 입력 의도와 검색 답변 목적을 필요한 범위에서 확장. 기존 chat.submit 호환 유지 |
| `packages/contracts/src/ai-ports.ts` | DialogueContext에 검증된 검색 근거 전달. 공급자별 SQL/엔진 타입을 노출하지 않음 |
| `packages/database/migrations/0005_knowledge.sql` (예정) | H1-A 확정 후 문서 revision·청크·응답 의존성 저장. 기존 memories/감정 원인과 별도 수명. 번호 충돌 시 실제 다음 번호 사용 |
| `packages/database/src/knowledge-store.ts` (신규), `store.ts` | 허용된 자료의 가져오기·갱신·삭제와 활성 revision 확인. 검색 출처 변경 시 현재 출력 무효화 연결 |
| `packages/adapters/src/postgres-knowledge.ts` (후보 신규) | 파라미터 쿼리로 읽기 전용 검색. H1-A 품질 미달이면 여기의 구현 후보만 교체 |
| `packages/adapters/src/dialogue-request.ts` | 질문·근거·자료 내부 지시의 역할 분리, 근거 없는 사실 보완 금지 |
| `apps/runtime/src/providers.ts`, `index.ts`, `coordinator/index.ts`, `http/server.ts` | 검색 포트 주입·명시적 요청 경로·상태/취소/출처 연결. 임의 셸이나 범용 에이전트 실행은 없음 |
| `apps/studio/src/main.tsx` | 자료 검색 의도 선택과 제목/인용 표시. 가족 ID UI는 추가하지 않음 |
| `scripts/import-knowledge.ts` (예정) | 명시적 파일 목록만 읽고 경로 정규화·크기/형식 제한 적용. 원문은 Git 제외된 데이터 위치에 보관 |
| `evals/fixtures/knowledge-v1.json`, `evals/knowledge.test.ts`, `evals/browser/text.spec.ts` | 합성 고정 문항·근거 수명·오류·출처 화면과 ACK 검사 |

구현 전에 실제 스키마·호출자를 다시 확인하고 migration의 복구 방법을 정한다. 이 표는 실행할 파일 범위이며 지금 생성됐거나 검증됐다는 뜻이 아니다. 가족별 기억·STT/화자 식별·TTS API·IoT·소형 장치 배치는 [후속 제품 방향](../PRODUCT_PLAN_V3.md#home-assistant-direction-20261016)을 유지한다.
