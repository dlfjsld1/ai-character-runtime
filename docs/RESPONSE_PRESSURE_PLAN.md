# 침묵 중 응답 압박 처리 — 2026-10-15

사용자 예시 “대답해 대답 안 해?!”와 후속 진행 요청을 반영한다. 욕설 없는 강압과 일반적인 응답 요청을 구분하고, 응답 요구가 자동 순응이나 감정 회복으로 이어지지 않게 한다.

실행 결과: [구현 및 검증](./RESPONSE_PRESSURE_RESULT.md). 첫 dev4/6은 보존했고 문항 정의를 명확히 한 후 dev6/6·새 대조4/4, 실제 Stage4/4를 확인했다. 처음 예정한6건 뒤 후보 수정 검증10건을 추가했으며 총 USD3를 유지했다. 최종 집중221·합성 DB52·타입 및 소스/ACK 감사 통과. 아래는 실행 전 성공 기준이다.

## 변경과 성공 기준

1. 선택형 Decisions v5에 response_pressure 독립 predicate를 추가한다. 현재 상대가 캐릭터에게 위협·윽박지름으로 답을 강요하는 경우만 yes. 정중한 재촉·일반 이유 질문·인용·타인 대상은 no. 기존 v2–v4 원문과 verifier 계약을 보존한다.
2. Core는 유효한 같은 상대의 withholding 기록이 있을 때만 압박에 대한 경계 발화를 선택한다. 불편함 .6 이상이거나 최근 유효 전달 문맥에 경계 발화가 있으면 침묵한다. 그 밖에는 한 문장으로 응답을 강요하지 말라는 뜻을 전한다. 삭제·실패·다른 상대의 기록으로 새 이유를 만들지 않는다.
3. 압박 자체로 감정 자극·관계 변화는 추가하지 않는다. 직접 공격은 독립된 기존 감정 경로를 따른다. 압박과 사과가 함께 있어도 압박을 감정 회복 권한으로 바꾸지 않는다. 의도적 숨김은 유지하고 생성에 원인을 공개하라고 요구하지 않는다.
4. 단위 재현/회귀, 합성 DB의 전달·재압박·실패·삭제·재시작, 고정 실제 판단 대조를 검증한다. 적격일 때 정상 앱→실제 Stage의 최초 경계/재압박 침묵/주제 전환을 확인한다. 실제 모델 결과와 fixture 결과는 분리한다.

파일 소유: contracts/conversation.ts(선택적 공급자 중립 압박 근거), adapters/openai-interaction.ts 및 새 v5 adapter(엄격 버전·문항 검증), character-core/index.ts(참여), database/store.ts(유효 전달 근거), adapters/dialogue-request.ts(한국어 생성), runtime/providers.ts 및 local-config.ts(명시적 선택), 각 해당 테스트. DB schema와 상태 구조는 늘리지 않는다.

실제 검증은 승인된 총 USD3 공유 원장과 기존 미확인 예약을 보존한다. 먼저 합성 판단6건, 적격일 때 Stage 최대4판단/3생성으로 제한한다. 새 unknown/예약 미정산 시 중단한다. 기본 Jev/Ollama와 기존 v4 결과는 자동 교체하지 않는다.
