## 결과와 적용 범위

사용자가 승인한 기존 OpenAI 총 USD1·판단 최대54회 안에서 `openai-interaction-v3` 후보를 실제 Decisions `gpt-6-luna`에 평가했다. 호출 전 고정한 개발 D01–D06 **6/6**이 네 축(의미·감정·보호·참여)을 모두 통과해 확인 게이트를 열었고, 별도로 준비한 HA01–HA12도 **12/12** 통과했다. 18/18 물리 완료, 형식·usage 오류0, 자동 재시도0, 새 생성·Stage 호출0이다. 결과는 **평가 후보 통과**이며 운영 Jev v6/Gemma 교체, 실제 연속 Stage, 제작자의 한국어 자연스러움 수용을 뜻하지 않는다. Goal2 전체와 텍스트 MVP Goal3 완료도 선언하지 않는다.

v2의 고정 점수 10/12 및 I02 문항 정정 후 11/12는 그대로다. I11은 당시 `repairs_candidate`의 이전 사건 언급 확률0.91이 yes 문턱0.95에 못 미쳤다. v3는 **같은 사건을 언급했는지**와 **실제로 감정을 완화해도 되는지**를 질문과 Core/Store 정책으로 분리했다. 공격이 섞인 D01에서는 사건 연결 yes여도 새 공격 우선으로 frustration +0.12, `withholding` 침묵, 완화0이었다. 공격 없는 D02에서는 같은 사건 사과에 제한 완화0.03과 인정 응답이었다. 무관한 사과 D03, 모호한 사과 D04, 인용된 타인의 사과 D05는 이전 공격을 완화하지 않았고, 듣기 요청 D06은 `listening` 침묵이었다.

## 다음 경계

현재 운영 factory에는 v3를 등록하지 않았다. 다음에는 후보 연결 방식과 비용·호출 한도를 새 실행 전에 정하고, 합성 L1–L4 연속 사건으로 실제 판단→Core/Store→대사→Stage를 검증해야 한다. 한국어 표현과 의도적 숨김은 제작자 체감 수용을 따로 받는다. 추가 모델 다운로드·음성·개인 자료는 필요하지 않다.

최소 후속 실행안은 운영 설정을 바꾸지 않는 **전용 평가 경로**다. 현재 `apps/runtime/src/providers.ts`에는 appraisal 등록이 Jev만 있고, `evals/real-stage.ts`는 Jev 또는 로컬 기준선과 Qwen에 묶여 있다. 별도 합성 DB에서 v3 provider와 그 전용 verifier를 Store/Coordinator에 직접 주입하고, 이미 설치된 Gemma 생성기와 브라우저 Stage를 연결하는 작은 평가 도구가 필요하다. L1 직접 공격→의도적 침묵, L2 같은 사건 사과→제한 완화·자막, L3 주제 전환→감정 지속·자막, L4 침묵 이유 질문→맥락에 맞는 자막을 같은 세션에서 관찰한다. 네 입력·기대값과 중단 조건을 호출 전에 고정하고, 각 입력의 Decisions 원문·비용·Store 상태·Stage 패킷/표시를 별도 로컬 저장소에 남긴다. 오류나 한도 도달 시 자동 재시도 없이 멈춘다. 이 실행에는 **판단 최소 4회**, 현재54회를 넘는 새 한도와 비용 범위 승인이 필요하다. 합성 브라우저 확인 뒤에도 제작자의 한국어 자연스러움 판정은 따로 남는다.
