## 구현 선택과 확인한 결함

명시적 검색 입력은 감정 판단 모델에 다시 분류시키지 않는다. 현재 감정 상태의 자연 감쇠와 말투 선택·출처 검증을 유지하면서 검색 답변을 반드시 계획한다. 일반 대화는 기존 감정 판단·참여 경로를 따른다. 검색 생성에는 질문과 검증된 청크만 전달하고, 최근 대화나 경험 기억으로 사실을 보완하지 않는다. 답변 상태는 answered/not_found/conflict이며 모델이 선택한 K1–K5를 서버가 현재 문서·revision·청크와 대응시킨다. 인용 형식 검사만으로 내용 정확성을 선언하지 않는다.

자료 변경 시 활성 검색만 취소하던 첫 구현에서 완료된 검색 답변이 일반 대화 문맥으로 다시 들어가는 문제를 독립 검토로 발견했다. 실제 DB에서 파생 일반 답변이 planned로 남는 것을 먼저 재현했다. 기존 출처 의존성 폐쇄를 재사용해 검색 답변과 파생 일반 답변·판단 문맥을 지우고 활성 응답을 취소하도록 수정했다. 입력 원본 삭제 때도 새 knowledge_context 필드를 제거한다. 최신 문맥 조회·검증에도 검색 revision 확인을 추가했다.

후속 **H1-F01 문장부호 품질**: C01의 `제공된 자료가 서로 달라.!`를 사례로 보존한다. 후속 수정 시 일반 대화와 근거 답변의 문장부호 처리 지점을 확인하고 중복 종결부호 처리 범위를 정한다. 성공 기준은 해당 사례의 자연스러운 종결, 소수점·말줄임표·인용문 보존, 사실·인용 ID·격식·문장 수 제한의 무변경이다. 저장된 원응답 재생과 집중 회귀부터 확인한다. 이번 마감에서는 코드를 추가 수정하거나 유료 재호출하지 않는다.

실제 개인 자료·웹 검색·STT/TTS·가족 식별·IoT·장치 배치는 H1 완료 범위가 아니다. 불편한 감정 장면은 합성 상태 통제이며 이번 실행에서 실제 감정 판단 모델이나 자연 도달을 추가 검증하지 않았다. H1 소스·문서의 게시 기준 태그는 `v0.2.0-home-assistant-h1`이다. [게시 점검](./PUBLICATION_REVIEW.md)을 거쳐 별도 커밋·annotated tag로 고정하며 기존 MVP 태그는 유지한다.
