# 입력 해석 구조 v2 — 2026-10-14

현재 상태: 아래 구조의 2026-10-14 로컬 구현·검증 뒤 2026-10-15 [실제 진단12 결과](./INTERACTION_V2_DEV12_RESULT.md)를 기록했다. 고정 기준10/12, I02 평가 기준 정정11/12이며 후보는 미채택이다. 아래는 실제 호출 전에 고정한 계획과 성공 기준이다.

사용자의 “구조나 질문 자체에 구조적 결함이 있는 것 아니냐” 검토와 “작업해” 지시를 반영한다. 문제는 단일 행위 선택의 중첩, 현재 발화 상대/인용 속 상대의 혼용, 세부 강도 불확실성의 전체 전파, 기술적/의미적 보류를 포함한 성공 합산이다. 기존 Jev·Decisions v1 점수와 실제 응답은 당시 기준으로 보존한다.

## 이번 계약

현재 메시지의 speaker/recipient는 입력 경로의 문맥으로 전달하고 이전 대화·침묵·원인과 구분한다. 인용·보고·가정·부정 속 행위를 현재 사용자의 행위로 승인하지 않는 기준은 각 의미 질문에 둔다. 별도 addressee 분류는 제거한다.

하나의 상호배타적 conversation_act 대신 이유 질문/듣기 요청/사과/대상 정정 네 개의 독립 참·거짓·불명 판정을 사용한다. 사과와 정정은 동시에 참일 수 있다. 원인 연결은 별도 판정이고 Store의 유효 출처·상대·시각·일회 marker가 최종 완화 권한을 결정한다.

직접 공격과 직접 칭찬도 독립 판정한다. 세부 강도는 별도 score 분포의 보수 하한을 쓴다. 예컨대 강도2/3에만 질량이 있으면 2까지 인정할 수 있으며 최빈 단계의 confidence로 사건 전체를 지우지 않는다. 강도 근거가 부족하면 감정 증가를 보류하되 확인된 현재 행위의 대화 처리는 유지한다. 판정 결과를 실제 사람의 감정 확률로 해석하지 않는다.

v2 전용 근거는 공급자/버전/event/revision/context hash를 검증한다. 기존 Appraisal 저장 형식과 DB schema는 유지하되 v2 bridge의 전역 uncertain은 기존 경로에 권한을 주지 않도록 보수적으로 둔다. v2는 검증된 개별 근거로 Core에 필요한 권한만 준다. 기존 v1 공급자는 같은 동작을 유지한다.

## 질문과 정책

9질문: 일반 발화 형태(question/greeting/statement), 이유 질문, 듣기 요청, 사과, 대상 정정, 원인 연결, 직접 공격, 직접 칭찬, 현재 캐릭터 평가 강도. 의미 predicate는 p≥.95를 yes, p≤.05를 no, 나머지는 unknown으로 고정한다. 이 새 문턱의 한국어 품질은 아직 미검증이며 기존 confidence .8과 같은 값으로 간주하지 않는다.

현재 직접 공격은 사과/정정보다 우선하고 원인 수선을 허용하지 않는다. 공격 확정·세부 강도 불명은 감정 증가0이어도 의도적 거리두기를 선택할 수 있다. 이유 설명과 듣기 요청이 동시에 확정되면 설명/수선 전에 듣기를 우선한다. 듣기나 공격의 의미가 불명하면 수선을 보류하고 필요한 확인을 요청한다. 모든 의미가 분명한 일반 발화는 일반 응답을 만든다. 공급자/형식/출처 실패는 기술적 보류이고 새 의도적 침묵 이유를 만들지 않는다.

## 성공 기준과 범위

구현 검토에서 보완한 우선순위: 이유 질문과 사과가 겹쳐도 설명 자체로 수선하지 않는다. 칭찬에 새 질문이 섞이면 질문을 먼저 처리한다. 일반 반복 칭찬/인사의 no_addition은 유지한다. AppraisalEvidenceVerifier의 선택적 validate 경계로 v2 출처 실패와 이미 실패 표시가 붙은 판정을 모두 중립화한다. 기존 v1 공급자 동작은 보존한다.

1. 구 구조에서 공격 강도 분산으로 자극0, 복수 행위 미표현, 정상 인용 발화의 defer, defer 포함 합격을 먼저 재현한다.
2. 복수 행위, 인용/제삼자/부정/가정, 혼합 공격+사과, 강도 분산, 일부 불명, 출처 변조를 단위 검사한다. 강도 불명만으로 일반 대화·이미 확정된 의미가 막히지 않아야 한다.
3. 실제 전용 테스트 DB에서 부정 감정 생성 → 주제 전환에도 지속 → 사과+정정에 제한 완화 → 반복 완화0 → 삭제/복구 및 선택 중 삭제를 검증한다. 의도적 숨김의 기존 회귀도 유지한다.
4. 평가 결과는 의미·감정·보호·참여를 각각 보고하고 응답/확인 질문/의도적 침묵/의미적 보류/기술적 보류를 구분한다. 정상 입력의 예상 결과가 응답일 때 defer를 합격으로 세지 않는다. 의도적 침묵이 정답인 입력은 응답을 강요하지 않는다.
5. 실제 v1 기록24건을 새 평가 관점으로 재분석하되 v2 모델 응답으로 위조하지 않는다. v2 합성 응답 검사는 공급자 의미 품질의 성공 증거가 아니다. 실제 공급자 검증과 Stage/제작자 수용은 별도로 남긴다.
