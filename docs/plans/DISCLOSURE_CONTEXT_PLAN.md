# 공개 의사와 감정 강도 분리 — D1–D3

2026-10-15 사용자 승인: 계획대로 진행하되 문제별 수정·검증 최대3회, 미해결은 기록 후 다음 작업으로 이동한다. 이전 r4 NOT_REACHED와 이전 정책 검증은 보존한다. 같은 후보를 재호출해 우연한 PASS를 얻지 않는다.

## D1 결정과 성공 기준

감정의 크기와 최근에 선택한 withholding의 공개 의사를 별도로 다룬다. Store가 검증한 같은 세션·상대의 최근4교환에 해당 침묵 입력이 남아 있고, 침묵 후10분 이내이면 Core에 해당 event ID를 전달한다. 10분은 기존 사건·수선 문맥의 유효 기간을 재사용한 제품 규칙이며 감정 측정값이 아니다. 새 DB 컬럼·wire·공급자 질문·장기 상태는 없다.

검증된 의미 기반 이유 질문에서 최근 withholding은 감정 수치와 무관하게 첫 설명을 partial로 한다. 같은 사건의 explain/partial이 정상 전달됐고 현재 사과·대상 정정이 모두 no라면 재질문에 deflect를 허용한다. yes/unknown이면 새 재질문 회피 권한을 주지 않는다. 예전 감정 기반 경로는 별도 유지한다. 첫 질문을 이유 없는 회피로 바꾸지 않으며, listening은 explain, 기록 부재/무효/실패는 unknown이다.

시간·최근 문맥을 벗어나면 새 공개 유지 권한은 끝나고 기존 감정 기반 규칙을 따른다. 감정0도 공개 의사 자체를 없애지 않지만, 감정0인 기록에 실제 불편함이 있었다고 생성 지시로 단정하지 않는다. 의미가 확실한 공격을 받아 대꾸하지 않기로 했다는 선택과 감정 크기를 구분한다.

## D2 파일과 검증

- `packages/character-core/src/index.ts`: 검증된 최근 침묵 ID를 입력으로 받는 공개 선택. 상태·원인·감쇠 불변.
- `packages/database/src/store.ts`: 기존 출처 검증과 최근 문맥에서 ID 전달. 전달 확인·삭제/수정·미전달 경계 유지.
- `packages/adapters/src/dialogue-request.ts`: 당시 감정값이0이면 불편함 단정 대신 응답하지 않은 선택으로 설명. 숨김과 unknown 구분 유지.
- Core·adapter·`evals/interaction.test.ts`: 확정/불확정 강도, 감정0, 첫 설명/재질문/화제 전환, 사과·정정 yes/unknown, 다른 상대, 삭제, 실패, 만료와 이력 탈락을 대조한다.
- `CHARACTER_DOMAIN_SPEC.md`와 현재 상태 문서: 현재 규칙·실행 결과를 맞추고 이전 증거는 덮어쓰지 않는다.

성공: 고정 G3-S16의 기존 partial/deflect 기대값은 그대로, 강도 불확정 재현에서도 해당 계획 도달. 감정 증가·초기화0, 기록 없는 원인 생성0, 새 일반 답변 차단0. 합성 대사는 자연스러움 증거로 계산하지 않는다.

## D3 실제 실행과 종료
