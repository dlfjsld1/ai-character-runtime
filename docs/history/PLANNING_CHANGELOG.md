### 같은 날 추가 정정 — 가족 구분 방식과 시점

첫 v3 개정에서 Codex가 가족 구분을 명시적 ID 선택으로 구체화하고 다음 개발 단계에 배치했다. 이는 사용자가 말한 미래 용도를 현재 요구와 구현 방식으로 앞서 확정한 해석 오류다. 사용자는 구현한다면 음성으로 구분할 것 같다는 방향만 밝혔으며 즉시 개발을 요청하지 않았다.

이에 현재 기획·MVP·검증·구현 계획·캐릭터 방향·인계·README를 함께 정정했다. 수동 ID 선택·가족 등록 UI는 계획에서 제거하고, 음성 기반 화자 구분은 별도 요청이 있을 때 검토할 구상으로 남긴다. 가족 구분→RAG라는 고정 순서도 제거했다. EM05/ER04의 내부 ID 검사는 기존 데이터 정합성을 보존하는 회귀 기준이며 가족 인식 기능의 성공 기준이 아니다. 코드·음성 기능·구버전 보관 원문은 변경하지 않았다.

## 2026-10-11 — 반복 적응과 응답 선택 분리

사용자는 오래 반복했을 때 모든 상황에서 감정 반응이 사라질 수 있는지 물었고, 개선 제안에 대해 **“그 방향으로 계획에 반영하고, 감정 증가량이 0이면 답변까지 막히는 것부터 수정해”**라고 승인했다.

수정 이유는 감정이 더 커지지 않는 상태와 답변할 필요가 없는 상태가 다르기 때문이다. 기존에는 같은 상대·종류의 자극 상한 때문에 증가량이 0이 되면 사회적 응답도 `ignore`될 수 있었다. 익숙한 칭찬을 편안하게 받아들이는 표현까지 막으므로 감정 런타임의 목적과 맞지 않는다.

- 이번 구현 범위: 0 증가량만으로 사회적 응답을 차단하는 조건 제거. 기존 15초 응답 제한, 대상·불확실성 판단, 감정·관계 수식, 600초 반복 창과 자극 상한은 유지한다.
- 승인된 후속 방향: 반복 감쇠를 확실한 반복으로 좁히고, 시간 경과에 따라 반복의 영향을 점진적으로 줄인다. 단순한 문구 변경을 새 자극으로 보상하지 않으며, 앞선 개선으로 부족할 때 새 사건·의미 구별을 보강한다.
- 범위 구분: 후속 방향은 미구현 계획이다. 새 Jev 필드·모델·API 추가, 음성·가족 인식 개발로 확대하지 않는다. 구버전 보관 원문과 과거 평가 결과는 유지한다.

구현과 검증 결과는 [개발 계획](../plans/IMPLEMENTATION_PLAN.md)과 [현재 인계](../STATUS.md)에 별도로 기록한다. 위 v3 개정과 가족 구분 정정의 “코드 변경 없음”은 각각 그 문서 작업 당시의 기록이다.

## 2026-10-11 — 선택적 침묵과 이유 유지·재접근

**요청자: 사용자. 이번 변경 범위: 기존 개선계획·명세·검증 기준·표현 방향·인계 문서. 코드·DB·wire·모델 설정은 변경하지 않았다.**

사용자는 입력마다 반드시 답하는 모습이 부자연스럽다고 지적하며, “답변할 필요 없어보이면(감정적이든 무슨 이유든) 그냥 처리만 하고 답변 안 해버리는 것도 좋지 않을까”라고 제안했다. 이어 “왜 말 안 해?”에 이유를 설명하거나, 실제로 모르는 것은 아니지만 “몰라”라고 회피하는 반응도 논의했다. 최종 요청은 **“의도적으로 침묵하고, 이유를 유지했다가 다시 말을 걸면 감정과 맥락에 맞게 반응하는 것까지 기존 개선계획에 반영해. 문서도 모순 없게 맞춰줘.”**다.

기획 v3·MVP EM03/EM06/EM08 및 새 EM09–EM10, 구현 E1–E4, 검증 ER02/ER05/ER07/ER08 및 새 ER09–ER11을 맞췄다. CHARACTER_PRESET의 예시는 고정 대본이 아닌 표현 목표다. CHARACTER_DOMAIN_SPEC §10.1이 내부 선택·최근 이유 수명의 계약을 소유하며 DATABASE_SPEC/RUNTIME_PROTOCOL에는 후속 저장·무출력 종료와 현재 미구현 경계를 표시했다. README/BUILD_HANDOFF는 문서 완료와 기능 미구현을 구분한다.

### 앞선 조사에서 유지한 개선 방법

감정 해석·지속 상태·대사 표현의 소유권을 유지하고, 일반 대화 prompt를 간결하게 맞춘 뒤 동일 조건에서 한 요인씩 비교한다. 발화 선택, 형식, 사실/이유 충실성, 감정 표현을 따로 평가한다. 아래 자료는 설계 참고이며 한국어 로컬 모델이나 현재 코드의 성공 증거가 아니다.

- [Chain-of-Emotion (2024)](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0301033): 평가한 감정 정보를 대사 생성에 연결하는 구조를 참고. 추가 모델 호출을 자동 도입하지 않음.
- [Open-LLM-VTuber Agent 문서](https://docs.llmvtuber.com/en/docs/user-guide/backend/agent/): 기본 대화 기억과 실험 기억 연결의 한계를 참고. RAG/새 DB를 현재 품질 문제의 자동 해법으로 삼지 않음.
- [Proactive Conversational Agents with Inner Thoughts (2025)](https://arxiv.org/abs/2501.00383), [Speak or Stay Silent (2026)](https://arxiv.org/abs/2603.11409): 내부 처리와 발화 참여 시점의 분리를 참고. 연구의 상시 사고 구조나 학습 절차 전체를 이번 MVP에 이식하지 않음.

이번에는 문서 정합성만 검토했다. E0의 Core 17/17·Coordinator 12/12·선별 DB 2/2·타입 PASS와 과거 grounded-v2 품질 FAIL은 원래 실행 범위로 보존한다. ER09–ER11은 미구현·미실행이며 옛 무응답을 새 의도적 침묵의 PASS로 재분류하지 않는다. 보관 원문, 제품 코드, 기존 테스트/fixture, 실행 데이터는 변경하지 않으며 commit/push·다운로드·유료 호출도 하지 않는다.

## 2026-10-11 — 화제 전환·재참여 뒤 감정의 연속성
