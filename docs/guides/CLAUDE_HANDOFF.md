## 1. 먼저 알아야 할 상황

이 프로젝트는 **대화와 사건에 따라 감정이 변하고, 이어지고, 선택적으로 표현되는 한국어 캐릭터 런타임**이다. 감정 단어를 넣거나 모든 입력에 대답하는 챗봇이 목표는 아니다. 잘 동작하면 자료 검색과 기억을 연결해 홈 비서로 확장한다.

지금의 핵심 공백은 새로운 사건·성향을 해석하는 모델의 의미 품질과 그 후속 운영 연결이다. **실제 생성8회→DB→Stage 자막 전달은 이미 통과했다.** 이 전달 검증에서 사건 판단·감정 상태·표현 의도는 합성으로 통제했고, 대사 생성만 실제 DeepSeek를 사용했다. 이것을 자연스러운 감정 판단까지 완성한 결과로 읽으면 안 된다.

사용자는 반복적인 감사와 같은 실패 문항의 끝없는 튜닝을 원하지 않는다. 확인한 문제를 작게 고치고, 같은 문제를 세 차례 수정·검수해도 남으면 실패와 영향을 기록해 후속으로 넘긴다. 기존 실패를 통과로 바꾸거나 테스트 기준을 출력에 맞춰 낮추지 않는다.

## 3. 현재 구조와 코드의 소유 경계

TypeScript ESM, Node22.19 이상, React/Vite Studio, Fastify runtime, **PostgreSQL**을 사용한다. 현재 DB는 SQLite가 아니다. 공급자 교체를 위해 포트와 어댑터를 나누는 방향이며 전체가 완벽하게 분리됐다고 가정하지 말고 직접 소비자를 확인한다.

```text
입력 → 사건/감정 해석 → Core 상태·참여·표현 계획
     → Coordinator → 생성 어댑터 → DB 응답·세그먼트
     → WebSocket Stage → shown/finished ACK → 완료

의도적 침묵 → 상태와 이유 저장 → 생성·자막 없이 다음 입력 수용
```

| 역할 | 먼저 볼 파일 |
|---|---|
| 교체 가능한 공통 포트 | `packages/contracts/src/ai-ports.ts` |
| 사건 평가 계약·근거·revision | `packages/contracts/src/affect-appraisal.ts`, `outcomes.ts`, `domain.ts` |
| 감정 계산·참여·표현 | `packages/character-core/src/event-affect.ts`, `index.ts`, `public.ts` |
| 사실/감정의 두 단계 해석 | `packages/adapters/src/split-event-interpreter.ts`, `outcome-probe.ts`, `appraisal-probe.ts`, `event-reference-codec.ts` |
| 대사 요청과 생성 | `packages/adapters/src/dialogue-request.ts`, `deepseek.ts`, `openai.ts`, `ollama.ts` |
| 예산 | `packages/adapters/src/deepseek-budget.ts`와 각 평가 실행기의 승인 연결 |
| 저장·출처·정정/삭제·출력 무효화 | `packages/database/src/store.ts`, `knowledge-store.ts`, `personal-fact-store.ts`, `migrations/` |
| 실행 조립과 공급자 등록 | `apps/runtime/src/providers.ts`, `coordinator/index.ts`, `http/server.ts` |
| 실제 자막 UI | `apps/studio/src/main.tsx` |

`DialogueGenerator`, `AppraisalProvider`, `EventInterpreter`, `ExperienceReadPort`는 서로 다른 역할이다. 새 두 단계 `EventInterpreter`가 있다는 사실만으로 runtime의 기존 `AppraisalProvider` 경로까지 교체됐다고 보지 않는다. 현재 `providers.ts`에 DeepSeek 대사 생성은 등록돼 있지만, 새 split 해석기가 운영 판단기로 등록된 것은 아니다.

Core는 감정 상태·참여·표현 정책을 소유한다. 생성 모델이 자기 출력으로 감정 정본을 바꾸거나 근거 없는 경험을 저장하게 하지 않는다. 두 단계 해석에서는 첫 단계의 사실 outcome을 고정하고 두 번째 감정 평가가 바꾸면 거부한다. 형식·참조 검사는 의미의 정확성까지 보증하지 않는다.

최신 전달 검증에서는 판단·감정·표현 의도를 통제했다. 자연 성향 해석이나 전체 CX8흐름의 품질 검증과 다르다. 실제 대사는 모두 단문이었다. 복수 문장과 동일 문장2개의 전달은 이전 **모의 HTTP→실제 DB/Chrome**에서9세그먼트·18 ACK로 검사한 증거다. 두 실행의 수를 합치지 않는다.

전용 Stage 실행기 감사에서 호출 수가 오류 시0으로 보고되던 문제와 실패 시 부분 증거가 빠지던 문제를 수정했다. 최종 집중133검사(실행기23·원장34·증거27·재생49), 타입 검사, DB/Chrome 오류5종을 통과했다. decoder 거부, usage 누락, 늦은 응답, 표시 중 취소, finished ACK 소실을 다뤘다. ACK 소실은 순번 불일치에 따른 연결 취소였으며 **연결을 유지한 ACK timeout 자체는 미검증**이다.

이 수치는 기존 저장 기록이며 이번 인계 작성에서 다시 실행한 검사는 아니다.

## 5. 현재 문제의 원인과 구분

### 우선순위 1: C2-P 수정 후 실제 의미 품질의 공백

이전 실제 결과의 핵심은 다음과 같다.

- A04: 성향과 무관한 좋은 결과에서 불필요한 긍정 평가를 생성.
- A05: 추천 미사용 보고만으로 긍정을 생성.
- A06: null 범위 평가가 episode 근거를 인용해 `affect_cross_scope_episode_evidence`로 거부됨. 거부 자체는 계약 방어가 정상 작동한 결과다.
- A01/A03: 추천 기여 주체와 실행자·보고자·대상의 혼동 우려. 이전 의미 보류 판정은 보존했고 role rubric을 보강했다.

구현한 수정은 `appraisal-probe.ts`의 `fixed-outcome-appraisal-v2` 지침, 범위별 근거 선택지, fixture의 role 기대값, scope별 실패 판정이다. 현재 입력의 독립 공감과 관련 성향의 감정은 허용하되 단순 favorable/미사용에서 감정을 발명하지 않도록 했다. 잘못된 근거를 자동 삭제하거나 감정량을0으로 덮어서 성공시키지 않았다.

지금 필요한 것은 새 실제 원문으로 이 개선을 확인하는 일이다. **전달 성공8건은 이 판단 모델 평가를 대신하지 않는다.** 실패를 DeepSeek의 해당 요청·버전·문항에 귀속하고, 런타임 전체 또는 다른 모델의 한계로 확대하지 않는다. 사용자는 OpenAI 조합에서 더 나은 응답을 경험했으며 OpenAI 크레딧은 소진됐다고 알렸다. 임의로 OpenAI 유료 경로를 재개하지 않는다.

### 후속 품질: 반복 수정은 종료한 상태

- `CX-SF01`: “모임은 오후 3시래, 확인해 봐.”처럼 이미 충분한 사실에 불필요한 재확인을 요구. 같은 지침을 세 차례 고친 뒤 후속으로 남겼다.
- 강한 긍정과 공개된 날 선 반응이 새 화제에서도 자연스럽게 이어지는지는 확인 부족. 내부 감정 지속과 출력의 연기 품질은 별도다.
- 최신 실제 formal 공개 대사의 “해결되셨다니”는 어색한 경어로 관찰했다.
- H1 문장부호 문제는 마감 때 후속으로 수용했다.

최신8응답에서 재확인 요구나 격식 왕복을 보지 못했다고 기존 결함을 해결로 바꾸지 않는다. 출력 어미를 사후 삭제하거나 고정 대사를 끼워 넣는 방식으로 통과시키지 않는다.

### 운영 확장 공백

O2의 사건 경험 저장·정정/삭제·설정 버전·새 감정 해석의 전체 runtime 연결과 O3의 실제 시나리오 평가는 미완료다. `action_episodes`·`affective_appraisals`·`affect_scopes`의 O2 저장 연결은 계획이며 구현됐다고 가정하지 않는다. H2-A의 명시적 사용자 정보와 기존 활동 기억을 같은 엔터티로 합치지 않는다. MyCemory 자동 쓰기·변경 알림·원자적 철회까지 이미 된 것으로 전제하지 않는다.

### 명령 선택

저장소 루트에서 실행한다. Node 타입 변환으로 실행하며 설치되지 않은 `tsx`를 전제로 하지 않는다. 이미 있는 의존성을 우선 사용하고 설치·모델 다운로드를 자동 진행하지 않는다.

```text
node node_modules/typescript/bin/tsc --noEmit -p tsconfig.json

node node_modules/vitest/vitest.mjs run --config vitest.integration.config.ts evals/affect-reconnect.test.ts evals/affect-reconnect-live.test.ts

node node_modules/vitest/vitest.mjs run --config vitest.config.ts packages/adapters/src/appraisal-probe.test.ts packages/adapters/src/split-event-interpreter.test.ts

node --experimental-transform-types evals/contextual-stage-replay.ts --recorded ${ARTIFACT_ROOT}/cx-stage-20261018-live1 --out ${ARTIFACT_ROOT}/new-stage-replay
```

명령은 필요한 범위를 고르는 예시다. 실행 전에 TEMP/TMP·Vite cache·리포터 출력과 테스트의 opt-in 환경을 읽고 승인된 AI 자료 폴더로 맞춘다. 단위 `vitest.config.ts`는 `packages/**/*.test.ts`, 통합 `vitest.integration.config.ts`는 `evals/*.test.ts`를 선택한다. 경로 인자만 주고 다른 config의 검사를 실행했다고 착각하지 않는다. opt-in 통합 검사가 skip이면 PASS로 세지 않는다.

재생은 추가 API/DB 없이 저장 증거를 검사하지만 현재 소스 hash가 기록과 다르면 거부한다. 파일 해시를 수동 갱신해서 옛 증거를 통과시키지 않는다. 이번 호출은 승인159회까지 완료했으므로 `contextual-stage.ts --live`의 옛151→159 인수를 재사용하지 않는다.
