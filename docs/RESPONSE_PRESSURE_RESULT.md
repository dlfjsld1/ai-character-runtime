# 침묵 중 윽박지름 대응 구현·검증 — 2026-10-15

이 문서는 압박4입력 실행 당시의 결과·비용 기록이다. 이후 v5 전체16입력, 복구 검사와 실행 후보 준비를 마쳤다. 최신 판정과 비용은 [텍스트 MVP 현재 상태](./TEXT_MVP_FINAL_STATUS.md)를 따른다. 이후 r4는 공개 목표2개 NOT_REACHED였고, 공개 의사 분리 수정 후 r5는16/16 PASS였다. 후속 표현 수정 뒤 r6도16/16 PASS였다. 이 문서의 압박 검증과 각각 구분한다.

선택형 Decisions v5와 OpenAI 생성 경로에서 구현했다. 사용자의 “대답해 대답 안 해?!”를 포함한 실제 대화4입력을 정상 앱과 Chrome Stage로 검증했다. 기본 Jev/Ollama 설정과 v2–v4의 이전 증거는 유지한다.

새 세션에서 실제 판단4·생성2·계수4회를 수행했다. 감정 상태 주입·저장 응답 재생 없이 발화2/침묵2, 표시 중 캡처2개와 완료 전달을 확인했다. 압박2회의 감정 자극은0이고 회복 marker도0이다. 불편함은 경과 시간에 따라 감소했으며 응답이나 주제 전환으로 초기화되지 않았다. 겉표현은 neutral이었다. 작은 내부 불편함과 감정 이유를 숨기는 경계 발화를 확인한 것이며, 강한 불쾌 표정이나 전반적인 한국어 품질을 증명한 결과는 아니다.

## 구현과 경계

- `conversation.ts`: 선택적 responsePressure 근거와 수선 금지. 기존 근거에는 값이 없으므로 새 권한이 생기지 않는다.
- `openai-interaction.ts`, 새 `openai-interaction-v5.ts`: 10번째 독립 압박 질문, v5 전용 엄격 원문 검증. 옛9문항과 새10문항을 서로 받아들이지 않는다. v4의 작은 칭찬 반응은 보존한다.
- `character-core/index.ts`: 같은 상대의 유효한 withholding 중 처음에는 짧은 경계 발화, 최근 전달된 경계가 있거나 불편함≥.6이면 침묵. 압박은 직접 공격과 별도이며 감정 자극을 임의 추가하지 않는다.
- `database/store.ts`: 기존 최근 문맥에서 완료 전달된 경계만 사용한다. 미전달·실패 출력을 전달된 경계로 세지 않으며 이유 삭제 시 진행 응답도 취소한다. 새 DB 테이블·상태 필드는 없다.
- `dialogue-request.ts`: 강요를 거절하되 이유를 공개하거나 기억 부재로 꾸미지 않는다. 굴복·보복·모욕·사과를 지시하지 않는다.
- `providers.ts`, `local-config.ts`: `APPRAISAL_PROVIDER=openai-decisions-v5`로 명시 선택. 기존 유료 사용·모델·공유 예산 검사를 유지한다.

반복 경계 억제는 기존 최근4교환 범위다. 계속되는 대화로 그 발화가 문맥에서 빠지면 다시 경계를 말할 수 있다. 모든 압박에 영구 침묵하거나 모든 요청에 강제로 답하게 만들지 않았다.

## 실패와 실제 판단 평가

최초 후보는 dev6 중4개 통과였다. 사용자 예시와 사과 뒤 명령은 압박 확률 .92/.93으로 기존 yes 기준 .95에 못 미쳐 unknown이었다. 이 결과를 보존했다.

문턱을 낮추지 않고 ‘욕설·명시적 협박 없이 반복 명령이나 복종 재촉도 압박’이라고 정의를 명확히 했다. ‘답할 것인지 추궁’과 ‘침묵의 이유 질문’도 분리했다. 수정 후보는 dev6/6 뒤 미사용 대조4/4가 압박 분류와 해당 경계 선택 기준을 통과했다. 급하지만 정중한 요청, 인용, 타인의 압박, 답변을 미뤄도 된다는 말은 압박 no였다. 마지막 대조의 일반 plan은 clarify였으므로 이10건을 모든 의미·자연스러움 기준의 만점으로 확대하지 않는다.

- Stage 종료: 세션 ended, 자식 프로세스 종료, 정산 완료, 이전 원장 보존, 새 미확인 호출0.

증거는 모두 `J:/ai/ai-character-runtime/` 아래에 있다: `pressure-probe-20261015/`(첫 실패), `pressure-probe-20261015-r2/`(수정 판단), `pressure-stage-20261015/`(실제 앱·원문·상태·Stage 캡처), `runtime-baseline-20261015/pressure-*.json`(집중 검사). 각 실행은 사전 기준과 소스 스냅샷을 보존한다.

## 비용·실행·남은 범위

현재 공유 원장은395 entry, 누적 판단132·생성63·계수200회다. 완료 모델 사용량 기반 추정 USD0.1575894, 예약 포함 차단용 합계 USD1.5292894 / 승인 USD3다. 실제 플랫폼 청구액은 미확인이다. 두 과거 unknown의 전액을 유지했고 이번 새 unknown/reserved는0이다.

일반 앱에서 사용하려면 기존 승인된 OpenAI 설정에 `APPRAISAL_PROVIDER=openai-decisions-v5`, `APPRAISAL_MODEL=gpt-6-luna`를 지정한다. 생성은 `DIALOGUE_PROVIDER=openai`, 기존 `gpt-6-sol` 설정을 사용한다. 유효한 공유 예산·키·호출 한도가 필요하다. 테스트 당시 한도132/63은 소진됐으므로 증거용 프로필을 그대로 복사해 새 호출을 시도하지 않는다. 실행 절차와 예산 설정은 RUNBOOK을 따른다.

최신 코드로 확인한 실제 Stage는 이4입력이다. 앞선 G3-S16은 당시 v4 소스의 결과로 남긴다. 한국어 말투의 제작자 취향 판단과 v5 포함 전체16입력 최종 회귀는 별도이며, 이를 기다린다는 이유로 자동 검증을 사용자에게 맡기지 않는다.
